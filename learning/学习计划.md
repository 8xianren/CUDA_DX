### 最终目标（F 之前的核心项目）

完成一个能执行下面流程的学习项目：

```text
读取 .gltf 或 .glb（成熟解析库 + 自讲 glTF 语义）
    -> 网格 / 材质 / 节点 / 相机
    -> D3D12 Vertex/Index Buffer、纹理、材质表
    -> BLAS（物体空间三角形）+ TLAS（实例变换）
    -> DXR RayGen 生成世界空间主射线
    -> TraceRay：Miss / ClosestHit / 阴影射线
    -> 路径追踪积分器（Lambert -> NEE -> MIS -> 多次反弹）
    -> 线性 HDR 累积、Tone Mapping、sRGB 呈现
    -> 对照本机 UE5 Path Tracer：DXR pipeline、MIS、SPP、随机序列
```

不要把这条核心路线说成“已经实现 UE Path Tracer”。对照的是同一类底层机制：世界空间射线、DXR 加速结构、NEE/MIS、线性累积。Lumen 是另一套实时 GI，不是本课模板。

### 每个 API 小节的固定讲法

1. 先给 Windows SDK 的真实声明或等价的官方签名，逐个说明参数类型、单位、有效范围和生命周期。
2. 画出 CPU 数据、GPU Resource、View/Descriptor、Command List、Queue 和 Fence 的关系；区分“描述资源的对象”和“真正拥有内存的对象”。
3. 列出资源在每个命令前后的状态，以及哪个队列/哪个 API 生产和消费数据；不能把 Resource State 当成跨 API 所有权的替代品。
4. 说明成功路径、典型错误、Debug Layer 能否发现，以及当前 demo 为控制变量省略了什么。
5. 用可运行 demo、读回、截图、Debug Layer、PIX/Nsight 或 sanitizer 验证结论；未实测的内容明确标注为推理或待验证。

### 明确不偷换概念

- `Input Layout` 是顶点字节解释规则，不是 Vertex Buffer 本身，也不是 HLSL 变量声明的同义词。
- Resource State 是 D3D12 对资源访问用途的声明；CUDA/D3D12 跨 API 的生产者/消费者顺序还需要 External Fence 或等价同步。
- sRGB/块压缩是数据编码与采样语义；纹理 tiled layout 是资源物理排布，二者不能互相解释。
- “Upload Heap 可 CPU 写入”不等于“Upload Heap 一定是 GPU 最佳读取位置”；性能结论必须结合 workload 和实测。

### 课程范围的明确边界

主线覆盖 D3D12 图形/计算核心，以及与游戏渲染直接相关的 DXR、Mesh Shader、VRS、HDR、Bindless 等高级能力。D3D12 Video（编解码/视频处理接口）属于同一 API 家族但不是网格渲染器所需路径；它会作为独立选修分支列出并按真实 SDK 接口讲解，不能假装已经包含在图形主线中。DirectML、DirectStorage、PIX 本身的全部功能也不是 D3D12 核心 API；需要时会明确标为相邻技术，而不是混称为 D3D12。

## 4. 阶段 B：重建真正的 D3D12 网格渲染器

这一阶段是 glTF 之前的基础。粒子中用 `SV_VertexID` 手写 quad 的代码只作为特例，不作为这里的顶点输入模型。

### B.0 R.0 总览：先建立渲染器整体流程

在进入任何新 API 模块前，先掌握 `learning/笔记/d3d12/R.0-D3D12渲染器整体流程.md`：窗口和设备如何启动，静态资源如何上传，命令如何从 CPU 录制到 GPU Queue，交换链如何呈现，Fence 如何保护帧资源，以及 R.1–R.7 每一步插入哪块能力。这个总览是后续所有模块的前置，不把“下一节”理解成只继续添加 API。

### B.1 R.1 顶点缓冲与 Input Layout

用 CPU 数组创建带 `POSITION` 和 `COLOR` 的三角形或立方体顶点；经历 Upload Heap staging、Default Heap GPU buffer、`D3D12_VERTEX_BUFFER_VIEW`、Input Assembler、HLSL `VertexInput`。

验收：真实顶点数组能被 Vertex Shader 读取并绘制；修改 CPU 顶点颜色后截图和读回结果都发生对应变化。

### B.2 R.2 索引缓冲与 `DrawIndexedInstanced`

为立方体或正方体添加 index buffer，解释顶点复用、`DXGI_FORMAT_R16_UINT/R32_UINT`、`IndexBufferView` 和 `BaseVertexLocation`。

验收：改用 `DrawIndexedInstanced` 后画面正确，索引越界和错误格式能被 Debug Layer 抓到。

### B.3 R.3 CPU 侧 Model/View/Projection 与 Constant Buffer

在 CPU/引擎侧构造模型、视图、投影矩阵，解释行列约定、转置、齐次坐标和 D3D12 CBV 的 256-byte 对齐；Vertex Shader 只应用上传的矩阵，不在 shader 中从相机参数构造矩阵。

验收：旋转模型、移动相机、改变 FOV/宽高比均正确；用一组已知点验证 Local -> World -> View -> Clip 的数值。

### B.4 R.4 深度缓冲与完整 3D 相机

创建 DSV、Depth-Stencil Resource、清深度、资源状态转换和深度测试；验证近处三角形遮挡远处三角形。

验收：交换绘制顺序画面不变；关闭深度测试后能复现遮挡错误；窗口调整大小后 viewport/scissor、投影和深度资源同步更新。

### B.5 R.5 纹理和材质

先支持一个简单的 RGBA 纹理：上传纹理 subresource、row pitch、SRV、静态 sampler、UV 插值和 alpha blend。再说明 sRGB 与线性数据的区别。

验收：纹理方向、UV、采样寻址和 alpha 都正确；纹理资源状态和 descriptor 绑定通过 Debug Layer。

### B.6 R.6 实例化网格

保留同一份网格 Vertex/Index Buffer，增加每实例的 World/颜色/ID 数据，解释 `SV_InstanceID`、实例缓冲布局和每实例常量的代价。

验收：一次 Draw 调用绘制多个不同变换的网格；实例数据更新不改变静态网格资源。

### B.7 R.7 渲染器最小架构与测试

整理 `Device/Queue/SwapChain/Resource/Shader/Mesh/Material/Camera` 的所有权边界，建立上传器和每帧资源；加入 CPU 侧 mesh、矩阵和索引的单元级校验。

验收：渲染器可以不依赖 CUDA 运行；关闭某个材质或替换网格不会破坏 frame fence；Debug Layer 运行干净。

## 4.1 阶段 R.X：DXR 硬件光追主线（核心）

这是本课程从“CPU 路径追踪原理”进入“D3D12 硬件光追实现”的关键阶段。DXR 不是路径追踪算法；它提供加速结构、射线调度和命中着色器执行能力。PT.1–PT.5 已经建立积分器数学，R.X 负责让同一套射线/可见性机制真正运行在 D3D12 + RTX 硬件上。

### R.8a DXR 能力查询与执行前提

查询 `D3D12_FEATURE_D3D12_OPTIONS5`、`RaytracingTier`、Shader Model 和资源绑定能力；记录 adapter、device interface、SDK/驱动和失败路径。本节不构建 BLAS/TLAS、不调用 `DispatchRays`，避免把“支持 DXR”误报成“已经运行 DXR”。

验收：`dxr_capability_probe.cu` 输出本机 RTX 5070 的 `RaytracingTier`；本机实测为 Shader Model 6.7、Raytracing Tier 1.1、Resource Binding Tier 3。

### R.9 BLAS：三角形几何与构建资源

使用 `D3D12_RAYTRACING_GEOMETRY_DESC`、`D3D12_RAYTRACING_GEOMETRY_TRIANGLES_DESC` 和 `D3D12_BUILD_RAYTRACING_ACCELERATION_STRUCTURE_INPUTS`，查询 `D3D12_RAYTRACING_ACCELERATION_STRUCTURE_PREBUILD_INFO`，区分 Vertex/Index Buffer、Scratch Buffer 和 Result Buffer 的数据布局、GPU 地址、资源状态、对齐和生命周期。

验收：用一个三角形构建 BLAS；验证 Result/Scratch 资源和 Fence 生命周期；构建前后 Debug Layer 无资源状态错误。RayGen/ClosestHit/Miss 属于后续 R.11，不把 BLAS 构建成功误报成已经执行 DXR 射线。

### R.10 TLAS：实例、变换与 glTF 节点的对应

讲清 `D3D12_RAYTRACING_INSTANCE_DESC` 的 `Transform`、`InstanceID`、`InstanceContributionToHitGroupIndex`、`Flags` 和 BLAS GPU 地址。明确 BLAS 保存物体空间三角形，TLAS 保存实例变换；这正好连接 glTF 的 node/world matrix。

验收：同一个 BLAS 放置多个实例；验证两个 Instance Desc 共享 BLAS GPU 地址、`Transform`、`InstanceID`、TLAS Prebuild/Result/Scratch 与 Fence；改变 glTF/CPU 节点变换后不重建静态 BLAS，只更新并重建/更新 TLAS。ClosestHit/InstanceID 颜色属于 R.11 之后，不在本节提前验收。

### R.11 Shader Table、Hit Group、State Object 与最小 DispatchRays

在 BLAS/TLAS 已存在后，建立 DXIL RayGen/Miss/ClosestHit、Hit Group、Global/Local Root Signature、State Object、Shader Table 与 `DispatchRays`。逐项解释 RayGen/Miss/Hit Group 表、Shader Identifier、Shader Record、Local Root Arguments、stride/size/alignment 和 `DispatchRays` 描述。对照 R.7 光栅化绑定：DXR 的 shader 选择不是一次 Draw 的 PSO 状态，而是由 State Object + Shader Table + 命中实例索引共同决定。第一版只输出 Miss/ClosestHit 颜色，不混入路径采样。

验收：真实 D3D12 窗口执行一次 `DispatchRays`；不同实例使用不同 Hit Group/材质索引；GPU 读到的 Local Root 数据与 CPU 写入的 record 字节布局一致；能力不足或 State Object/Shader Table 创建失败时打印 HRESULT 并明确失败。

### R.12 DXR 阴影射线与 PT.5 NEE 对接

把 PT.5 的 CPU 有限阴影射线迁移到 HLSL `RayDesc`：`Origin=x+epsilon*n`、`Direction`、`TMin`、`TMax=distance-epsilon`。解释 `RAY_FLAG_ACCEPT_FIRST_HIT_AND_END_SEARCH`、AnyHit/Miss/ClosestHit 的用途，并明确 DXR 不会自动理解“阴影射线”语义。

验收：无遮挡返回可见，挡板返回不可见；光源后的物体不能遮挡；单面发光与 `cosθL` 约定和 CPU NEE 一致。

### R.13 引擎式相机、DXR 直接光成像与渐进累积（2026-10-10 重启）

按学习者要求重新开始课堂。沿现代引擎的 View/Projection、视图参数、渲染资源和逐帧更新流程讲解；以 UE 的机制作对照，D3D12/DXR 独立实现。旧 `dxr_camera` 保留作解析相机与几何诊断参考，旧测试不计作新版各小节的完成验收。详细约定见 `笔记/d3d12/R.13-重启计划与相机约定.md`。

### DXR 加速结构的原理边界（在 R.10/R.11 中随 API 一并说明）

BLAS/TLAS 在概念上属于以 AABB 层次剔除为核心的 BVH 家族：BLAS 组织局部几何，TLAS 组织实例包围盒并引用 BLAS。它不是课程中另行实现的八叉树或 BSP，也不能据此断言驱动内部一定是二叉树。实际节点宽度、压缩/量化、叶节点重排、构建/重建/更新策略和硬件布局由 D3D12 驱动与 GPU 管理，API 不保证内部格式，应用不能直接遍历或修改这些节点。R.10/R.11 只在真实 `InstanceDesc`、Prebuild Info、Build、`TraceRay` 调用链中解释这一层，不新增脱离 DXR 的“CPU 假 BVH 可视化”验收。

核心项目使用 DXR，不在积分器中手写三角形求交。PT.9 保留为核心完成后的 CUDA 对照扩展：如确有需要，再实现 CUDA BVH、Megakernel、Wavefront，用于学习执行模型和性能；它不替代 DXR 后端。共同概念是射线/AABB/三角形/最近命中；实现、所有权、构建和调度模型不同。

## 4.2 PT：DXR Path Tracer 的积分器课程

PT.1–PT.5 已先用 CPU 解析参考建立地基；R.9–R.13 先完成 DXR 执行后端和最小 Lambert 路径；C/D 再把 glTF 场景接入同一个 BLAS/TLAS 和积分器；最后 PT.6–PT.10 在这个 DXR + glTF 基础上依次完成 MIS、多次反弹、材质和显示评测。

PT.1–PT.10 按上述线性顺序建立可验证的 DXR Path Tracer。核心项目完成后，再学 PT.11 ReSTIR，PT.12 再学辐射缓存
与 NVIDIA NRC 原理，并对照本机 UE5 源码里的 Lumen 与 Path Tracer。不要把 Lumen
实时 GI、UE Path Tracer、NVIDIA NRC 三个名字混成同一种算法。

必须先区分三个层次：

```text
光线追踪（Ray Tracing）
    = 用射线生成、几何求交和可见性查询构造图像的一大类方法

路径追踪（Path Tracing）
    = 用随机路径和蒙特卡洛估计求解渲染方程的一种光线追踪算法

DXR / OptiX
    = 提供加速结构、遍历或着色执行能力的 API/框架，不等于路径追踪算法本身
```

课程实现边界：CPU 参考用于数学验收，DXR 用于核心生产后端；不要求先完成 CUDA BVH 才能做 DXR Path Tracer。所有颜色累积在线性 HDR 空间完成，Tone Mapping
之后才编码为 sRGB。随机图像必须保存种子、分辨率、samples per pixel（SPP）、最大
反弹数和场景参数；不能只凭一张“看起来合理”的图判断正确性。

### PT.1 辐射度量学、立体角与渲染方程

区分 Radiometry（物理辐射能量）和 Photometry（按人眼视觉响应加权）；掌握辐射通量
`Phi [W]`、辐射强度 `I [W/sr]`、辐照度 `E [W/m^2]`、辐亮度
`L [W/(m^2 sr)]`、立体角和投影余弦。逐项解释渲染方程中的入射辐亮度、BRDF、
`cos(theta)`、积分域和单位为什么能够闭合。

验收：用 CPU 数值积分验证常量半球函数的立体角为 `2*pi`、余弦积分为 `pi`；给定
Lambert 反射率和均匀入射辐亮度时，数值结果与解析结果在设定误差内一致。

### PT.2 相机射线、几何求交与可见性

从像素中心或像素内样本生成世界空间射线，明确相机基向量、FOV、宽高比、射线参数
`P(t) = O + tD` 和有效区间 `[tMin, tMax]`。实现球体、三角形、AABB 求交，讲清
Moller-Trumbore、重心坐标、最近命中、正反面法线、自相交 epsilon 与数值误差。

验收：CPU 单元测试覆盖命中、漏过、平行、边界和背面射线；输出法线图、深度图和
primitive ID 图，并让已知射线的 `t`、重心坐标和命中 ID 与手算值一致。

### PT.3 蒙特卡洛积分、随机变量与 PDF

从期望值推导估计量 `f(X) / p(X)`，说明概率密度函数（PDF）的定义域和单位、无偏、
一致性、方差及 `1/sqrt(N)` 收敛规律。实现可复现 RNG，比较均匀采样、分层采样和
重要性采样；明确“随机”不等于“随便取点”。

验收：对有解析答案的一维积分和半球积分运行多组种子；验证 PDF 数值归一化，记录
样本数增加时的均值、方差和误差曲线，并能复现同一种子的逐样本结果。

### PT.4 Lambert BRDF 与余弦加权半球采样

从 `f_r = albedo / pi` 解释 Lambert BRDF 为什么带 `1/pi`，建立局部切线空间，
实现均匀半球与余弦加权半球采样及对应 PDF。逐项拆开路径权重
`Li * f_r * cos(theta) / pdf`，说明错误 PDF、漏乘余弦或重复乘余弦会造成什么偏差。

验收：采样方向均位于正确半球，PDF 积分为 1；白炉测试不凭空增能；在相同 SPP 下，
余弦加权采样相对均匀半球采样具有更低的实测方差。

### PT.5 直接光照、阴影射线与 Next Event Estimation

加入点光源和面积光源，显式从光源采样一个点并发射阴影射线。推导面积域 PDF 到立体角
PDF 的 Jacobian，处理距离平方、光源法线、遮挡与发光面单/双面约定。解释 Next Event
Estimation（NEE）为何能更高效地发现小光源，但不能单独代替完整多次反弹。

验收：无障碍时直接光照与 CPU 解析/高样本参考一致；加入遮挡物后硬阴影或软阴影位置
正确；改变面积光源大小时亮度和阴影变化符合固定功率或固定辐亮度的明确约定。

### PT.6 DXR Path Tracer：BSDF Sampling、NEE 与 MIS（glTF/DXR 接入后）

在 R.13、C/D 的 DXR + glTF 场景基础上，比较“沿 BSDF 采样”和“直接采样光源”各自擅长的路径，使用 Balance Heuristic 和
Power Heuristic 合并两种估计。讲清两边 PDF 必须在同一测度下比较，以及 delta 光源/
镜面事件为什么需要特殊处理，避免同一条光路重复计数或权重错误。

验收：分别输出 BSDF-only、NEE-only 和 MIS 结果；在相同 SPP、固定种子集合下比较均方
误差和方差，MIS 不改变参考均值且能降低包含小光源或高光场景中的明显噪声。

### PT.7 DXR Path Tracer：多次反弹、路径吞吐量与俄罗斯轮盘赌

在 PT.6 MIS 已正确接入后，用 DXR ClosestHit/RayGen 的 payload 建立完整路径循环：累加发光、采样 BSDF、更新路径吞吐量 `beta`、生成下一条射线。
严格区分固定最大反弹深度和俄罗斯轮盘赌：前者截断路径并可能引入偏差；后者按存活概率
随机终止，存活路径必须除以该概率，才能保持估计无偏。讨论何时开始轮盘赌、存活概率
如何由吞吐量估计，以及概率上下限对方差和性能的影响。

验收：记录每个深度的存活路径数和平均吞吐量；开启/关闭俄罗斯轮盘赌的多种子均值在
置信误差内一致，而平均追踪深度下降；故意省略“除以存活概率”时测试能够暴露系统性变暗。

### PT.8 DXR Path Tracer：glTF 材质、金属、介质、Fresnel 与微表面 BRDF

在 glTF C.5 的材质字段基础上，实现理想镜面、介质折射、全反射和 Fresnel，再学习 GGX/Trowbridge-Reitz 法线分布、
Smith 几何遮蔽和 Schlick Fresnel。区分金属与非金属参数、粗糙度和 alpha 的映射、
BRDF 计算与 BRDF 采样，并明确简化材质与 glTF metallic-roughness 的后续映射边界。

验收：已知入射角的反射/折射方向和 Fresnel 值通过 CPU 测试；白炉测试检查能量守恒；
粗糙度扫描没有 NaN、黑斑或能量爆炸，镜面极限使用明确的 delta 处理。

## 5. 阶段 C：glTF/GLB 场景输入（核心路径追踪资产管线；R.13 之后）

**授课约定（2026-10-16）**：C.1–C.6 各自为一个完整授课单位，不合并、不再拆子课；按第 2 节 C/D 专门约定精简 glTF 细节，重点是资源如何解析成渲染需要的数据。

glTF 是 DXR Path Tracer 的主教学场景格式。2026-10-16 选型：使用成熟的多格式导入库 Assimp，覆盖 glTF/GLB，并以 FBX、OBJ 等常见格式作为后续兼容性样本；2026-10-16 已接入固定版本 Assimp 6.0.2，glTF/GLB、OBJ、FBX 探针及四类失败输入测试通过；GLB 导出回环丢失相机对象已记录，C.2 已于 2026-10-16 授课完成。文件容器和 accessor 解码交给库，不自行实现 glTF/FBX 解析器。我们实现“Assimp 统一 CPU 场景 → 自有 Mesh/Material/Instance → D3D12/DXR 资源”的适配层，重点理解对象关系、布局、坐标、材质与所有权。统一场景与原始 glTF 对象不保证一一对应；库支持的格式和我们渲染器支持的功能也必须分别记录。Assimp 官方资料：https://github.com/assimp/assimp 。FBX 专项兼容性有需要时再评估 ufbx，不提前引入多个导入库。

### C.1 glTF 对象模型

掌握 `asset`、`scene/scenes`、`node/nodes`、`mesh/meshes`、`primitive`、`accessor`、`bufferView`、`buffer`、`material`、`texture`、`image`、`sampler`、`camera` 的关系。

必须能画出并解释这条引用链：

```text
primitive.attributes["POSITION"]
    -> accessor
    -> bufferView
    -> buffer
    -> 二进制字节
```

### C.2 `.gltf` 与 `.glb` 容器

理解 `.gltf` 的 JSON 与外部/内嵌资源，以及 `.glb` 的 12 字节 Header、JSON Chunk 和可选 BIN Chunk；GLB 仍可能引用外部资源。接入 Assimp 完成文件读取、失败检查与错误报告。magic、version、chunkLength、对齐和 URI/Data URI 只讲必要概念，不手写容器解析器。

验收：同一个模型的 `.gltf` 和 `.glb` 版本能得到相同的内部网格统计；截断文件、错误 magic 和错误 chunk 长度应被拒绝，报告输入路径与库诊断，不承诺库一定提供字节级错误位置。

### C.3 accessor/bufferView 解码

理解 `componentType`、`type`、`count`、`byteOffset`、`byteStride`、`normalized` 如何描述原始数据，实际解码由 Assimp 完成。读取其已解码网格，转换成自有顶点/索引结构；第一版处理 `POSITION/NORMAL/TEXCOORD_0/COLOR_0` 和索引。明确区分源文件编码、库的 CPU 表示与 GPU 布局；用样本验证无索引 primitive 和不同整数索引格式，不自行重写 accessor 解码器。

建议的内部格式：

```cpp
struct Vertex {
    float position[3];
    float normal[3];
    float uv[2];
    float color[4];
};

struct SubMesh {
    std::vector<Vertex> vertices;
    std::vector<uint32_t> indices;
    uint32_t materialIndex;
};
```

验收：固定样例记录 count、属性偏移与 stride；用独立已知数学数据验证库解码与自有结构，不重写通用解码器。覆盖交错布局、normalized颜色、不同索引宽度、无索引及缺失属性，并在Importer析构后检查深拷贝结果。

### C.4 mesh、primitive 与 node 层级

把一个 mesh 的多个 primitive 转成多个 SubMesh；处理 `TRIANGLES`，再解释 `TRIANGLE_STRIP`/`TRIANGLE_FAN` 的转换。遍历 node 层级，组合 TRS 或 matrix，计算 World Matrix 和 parent-child 关系。

验收：含多个 node/primitive 的模型位置正确；改变父节点变换会同步影响所有子节点。

### C.5 材质与纹理

第一版支持 `baseColorFactor`、`metallicFactor`、`roughnessFactor`、`baseColorTexture`、`normalTexture`、`occlusionTexture`、`emissiveTexture`、`alphaMode`、`doubleSided`。说明 base color 常用 sRGB，而法线、金属度和粗糙度通常按线性数据处理；解释 metallic-roughness 纹理的 G/B 通道约定。

验收：无纹理材质默认值、带纹理材质的因子/槽位/采样器/颜色空间及图像编码流归属正确；没有可选纹理使用默认值，显式引用却缺失文件应报错。C.5只完成CPU导入，像素解码、GPU上传与绘制在D.1/D.3验证，完整BRDF着色在后续PT材质课程完成。

### C.6 解析器健壮性与范围控制

第一版使用 Khronos glTF Validator 校验原始资源，再执行课程能力检查和 Assimp/C++ 适配。当前仅接收无扩展的静态核心 glTF；Skin、Animation、Morph Target、Draco、Meshopt、KTX2 等不在当前支持范围。遇到不支持内容整次拒绝并说明原因，不默默丢弃。可绘制部分的降级预览暂缓，未来必须显式定义丢弃项和引用处理。

验收：通过带校验入口验证错误文件、越界 accessor、未对齐 byteOffset、未知 componentType 与不支持特性。直接调用 LoadCpuScene 不自动运行 Validator，不能视为完整规范校验。C.6 已完成底层11项边界探测、组合入口8项测试及C.3–C.5回归；CPU导入成功不代表GPU着色已实现。详见 `笔记/d3d12/C.6-支持范围与导入健壮性.md`。

## 6. 阶段 D：把 glTF 接入 D3D12 + DXR（核心路径追踪场景；C 完成后）

**授课约定（2026-10-16）**：D.1–D.4 各自为一个完整授课单位，不合并、不再拆子课；glTF 背景简述，GPU 资源、同步和 DXR 接入的关键机制讲清。执行第 2 节 C/D 专门约定。

### D.1 CPU 解码结果到 GPU 资源

将内部 `SubMesh` 扁平化为 Vertex/Index Buffer；实现上传器、Default Heap、资源状态和视图创建。材质表映射到 descriptor heap，纹理上传独立于 mesh 上传；同时为每个 primitive 准备 BLAS geometry 描述和命中材质索引。

**必须在课堂中说明的资产管线对照（学习者2026-10-20要求）**：本课“运行时解析glTF→CPU数据→GPU上传”是基础实现，不是现代引擎唯一加载路径。区分DMA搬运、格式解析/转换和GPU解压；说明离线导入/Cooking可提前生成目标平台资源，将CPU所需元数据、碰撞/逻辑数据与GPU大块数据分离。CPU可先读布局、大小、格式、包围盒和资源引用，再分配GPU资源并调度加载，无需先读取每个顶点或纹素；如果CPU算法确实需要完整数据，应说明保留CPU副本、专用简化表示、GPU计算或必要读回的选择及内存/同步成本。介绍DirectStorage作为可选加载路径，但不宣称必然绕过系统内存，也不将其等同于自动解析glTF、创建资源或完成着色。UE具体支持需按版本、平台和资源类型核实，不能将Cooking等同于已启用DirectStorage。本节讲清机制与边界，不增加子课，不将DirectStorage实作列为当前验收。参考与详细说明见 `笔记/d3d12/C.6-支持范围与导入健壮性.md` 的课后补充。

验收：加载最小 glTF 样例，完成光栅化预览和 DXR BLAS 几何输入；输出 mesh、primitive、vertex、index、texture 数量与 BLAS geometry 数量。

### D.2 节点遍历与每对象常量

每帧遍历活动 scene 的 node，计算 `worldMatrix`；光栅化预览使用 Object Constants，DXR 使用同一矩阵写入 `D3D12_RAYTRACING_INSTANCE_DESC::Transform`，并把 InstanceID/材质索引传给 hit shader。相机数据进入 RayGen 常量。

验收：同一 mesh 被多个 node 引用时只创建一份网格/BLAS，但每个 node 的 World Matrix/TLAS instance transform 不同。

### D.3 纹理色彩空间与采样验证

验证图像 MIME type、外部 URI、Data URI、纹理坐标和 sampler 的 wrap/filter；在 DXR hit shader 中先完成 base color，再接 normal、metallic-roughness、emissive 和 alpha 规则，不把完整 PBR 一次性混入解析器。

验收：至少一个官方 glTF 样例纹理显示方向正确，sRGB/线性设置有明确代码和文档依据。

### D.4 解析器与渲染器边界整理

解析器只负责“文件 -> CPU 结构”；资源工厂负责“CPU 结构 -> D3D12 资源”；渲染器负责“节点/材质 -> 命令列表”。这样后续替换 Vulkan 或离线导入工具时不会重写 accessor 解码。

## 8. 阶段 F：抗锯齿、时域重建与超分（核心完成后的附加课程）

这是一条建立在完整 D3D12 渲染器之上的图像质量路线，不把几个名字相似但目标不同的技术混成一类：

```text
MSAA                 = 同一帧内增加几何覆盖采样
FXAA                 = 对已经生成的单帧图像做空间边缘滤波
TAA                  = 利用当前帧和历史帧做时域重建与抗锯齿
FSR/DLSS/XeSS        = 以较低内部分辨率重建较高输出分辨率，部分模式兼具抗锯齿
Frame Generation     = 在真实渲染帧之间生成额外显示帧，不等于超分，也不降低输入延迟
```

默认在 D/E 主线结束后学习。F.1–F.5 以及 F.6 的基础空间缩放由我们在当前 D3D12 渲染器中亲手实现；F.6 的 NIS 和 F.7–F.9 使用官方 SDK 或官方参考实现，不自行仿造闭源神经网络核心。

### F.1 MSAA 与 Alpha-to-Coverage

学习 `D3D12_FEATURE_MULTISAMPLE_QUALITY_LEVELS` 能力查询、多采样 Color/Depth Resource、PSO 的 `SampleDesc`、多采样 RTV/DSV、sample coverage、`ResolveSubresource` 及其前后资源状态。把 Alpha-to-Coverage 放在这一节，解释它如何把 Alpha 转换成 MSAA sample coverage，以及它为何适合草叶、铁丝网等裁剪材质，却不能代替通用透明混合。

验收：在 1x/4x MSAA 间切换；斜边和 alpha-cutout 几何产生可见差异；Resolve 到单采样交换链 Back Buffer；Debug Layer 无状态或采样数不匹配错误。

### F.2 离屏渲染与全屏后处理框架

建立 HDR/线性空间的离屏 Color Target、对应 RTV/SRV、全屏三角形、Render Target 与 Shader Resource 状态转换，以及必要的 ping-pong 资源。明确后处理输入、输出和交换链 Back Buffer 不能在同一时刻形成非法读写反馈。

验收：先用恒等后处理完整复制画面，再加入可开关的灰度或曝光操作；Resize 后离屏资源、描述符和 viewport 同步重建。

### F.3 FXAA

讲清亮度估计、局部对比度、边缘方向搜索和沿边采样。FXAA 只读取当前完成帧，不需要运动矢量、深度或历史帧；代价较低，但容易软化纹理细节，也无法根治运动中的时域闪烁。

验收：使用同一场景对照 No AA、FXAA 和 MSAA；记录 GPU 时间，并观察细线、远处几何和高频纹理，而不是只看一条静止斜边。

### F.4 时域重建的输入契约

先独立完成 TAA 和时域超分共同依赖的数据：Halton 等亚像素 Jitter、当前/上一帧 View-Projection、每像素 Motion Vector、深度、历史颜色和曝光。逐项明确 Motion Vector 的方向、坐标空间、单位（UV、内部渲染像素或输出像素）及是否包含 Jitter，不能把不同 SDK 的约定互相套用。

同时定义 Camera Cut、窗口 Resize、FOV 改变、动态分辨率切换、物体首次出现和传送时的 History Reset 规则。

验收：用静止相机、相机平移、旋转物体和遮挡显露四组画面验证运动矢量方向；提供可视化 Pass，并用 CPU 计算的已知点检查向量数值。

### F.5 教学版 TAA

实现历史重投影、越界/深度不连续拒绝、Neighborhood Clamp（可对照 RGB 与 YCoCg）、历史权重和可选锐化。重点分析 ghosting、disocclusion、闪烁、过度模糊和透明物体的历史污染，而不是只得到一张“看起来更平滑”的静态截图。

验收：可逐项关闭重投影、历史拒绝和 clamp，复现对应错误；Camera Cut 后首帧不读取无效历史；动态物体边缘没有持续拖影。

### F.6 动态分辨率与空间超分基线

区分内部渲染分辨率、显示分辨率和动态分辨率比例；处理 viewport、纹理尺寸、运动矢量尺度、Mip LOD 与 UI 分辨率。先以双线性/双三次和 NVIDIA Image Scaling 等空间方案建立基线，再与时域方案比较。

验收：内部比例在 50%–100% 间变化时画面尺寸、UV 和 UI 均正确；记录图像质量、GPU 时间与显存变化。

### F.7 AMD FidelityFX Super Resolution

使用 [AMD FidelityFX SDK](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK) 的当前官方接口接入 FSR。逐项核对颜色、深度、Motion Vector、Jitter、曝光、Reactive Mask、透明/合成遮罩及资源状态；具体可用版本、后端和硬件要求以接入时 SDK 文档为准。

验收：实现 Native、Quality、Balanced、Performance 等可比较模式；Camera Cut、Resize 和动态分辨率能正确重建/重置上下文；不把 FSR Frame Generation 混入本节的超分结果。

### F.8 NVIDIA DLSS、Streamline 与 Intel XeSS

分别通过 [NVIDIA DLSS](https://github.com/NVIDIA/DLSS)、[NVIDIA Streamline](https://github.com/NVIDIA-RTX/Streamline) 和 [Intel XeSS](https://github.com/intel/xess) 学习官方集成方式。重点比较三者的输入契约、特性查询、上下文生命周期、资源标签、Resize/Reset、HDR/曝光和失败回退，而不是比较品牌宣传数字。

DLSS 的部分插件和模型以官方预编译二进制分发，不能假定 `git clone` 后已经取得所有运行组件；课程接入前必须核对 Releases、许可证和目标硬件支持。

验收：至少完整接入一个时域超分 SDK；其余两个完成接口和输入映射对照。SDK 不可用、硬件不支持或初始化失败时，渲染器能回退到 TAA/空间缩放，而不是黑屏或崩溃。

### F.9 帧生成、帧节奏与输入延迟

单独讲真实渲染帧、插值帧、光流/运动矢量、Present 调度、UI 合成位置和延迟控制。区分“显示 FPS 增加”“真实模拟/输入采样频率”和“端到端输入延迟”；结合 Streamline/Reflex 或 FidelityFX Frame Generation 的当前官方方案学习，不手写并宣称等价于商业帧生成算法。

验收：日志明确标出真实帧与生成帧；UI 不产生插值伪影；分别记录 GPU 帧时间、显示帧率、帧节奏和可测的延迟指标。

### F.10 图像质量与性能评测

固定场景、相机路径、内部/输出分辨率、VSync 和曝光，观察静态锐度、运动稳定性、细线闪烁、遮挡显露、透明粒子、粒子拖影和 Camera Cut。使用 GPU timestamp/PIX/Nsight 记录成本，并保存对照截图或帧序列；单帧截图不能代替时域稳定性评价。

参考仓库边界：

- [NVIDIA Image Scaling](https://github.com/NVIDIAGameWorks/NVIDIAImageScaling) 可作为空间缩放基线。
- [Sascha Willems Vulkan](https://github.com/SaschaWillems/Vulkan) 适合对照 Vulkan 的 MSAA 与资源配置，但不是抗锯齿库。
- [Unity Graphics](https://github.com/Unity-Technologies/Graphics) 和 [Unity Post Processing](https://github.com/Unity-Technologies/PostProcessing) 适合研究生产级时域/后处理架构，不作为当前 D3D12 C++ 渲染器的直接依赖。
- 引入任何 SDK 或参考代码前，必须核对当前版本、许可证、二进制分发方式和平台限制。

## 9. 阶段 G：体渲染、NeRF 与 3D Gaussian Splatting（附加课程）

这是一条建立在 CUDA 性能基础、D3D12 完整渲染器和 CUDA/D3D12 互操作之上的高级课程。它不把三个概念混为一谈：

```text
体渲染（Volume Rendering）
    = 沿相机射线对吸收、透射和发光进行积分的一类渲染方法

NeRF（Neural Radiance Field）
    = 用神经网络表示连续辐射场，再用体渲染方程生成像素

3D Gaussian Splatting（3DGS）
    = 用一组显式三维高斯表示场景，将高斯投影成屏幕椭圆后排序并合成
```

默认先完成 B–E 主线。G.1–G.3 可以在 E 阶段完成后单独学习；G.6–G.8 会直接复用 R.5 的透明合成、R.6 的结构化实例数据、E 阶段的 CUDA/D3D12 共享资源和阶段 2/4/6/7 的 scan、原子操作、共享内存、访存与性能分析知识。F.2 的离屏渲染框架对最终合成有帮助，但不是开始 G.1 的硬性前置。

课程实现边界：我们会亲手实现教学版体渲染器和 3DGS 前向渲染核心，以看清数据布局、线程映射、排序和合成；完整 NeRF/3DGS 训练涉及自动微分、优化器和成熟算子，先用 PyTorch、tiny-cuda-nn 或上游参考实现建立可信基线，再选择关键 CUDA 算子拆解，不把一个简化 demo 冒充生产训练系统。

### G.1 发射-吸收体渲染方程

从相机像素生成射线，推导连续积分及其离散形式：密度 `sigma`、步长 `delta`、样本不透明度 `alpha = 1 - exp(-sigma * delta)`、透射率 `T` 和前向颜色累积。解释它与普通 Alpha Blend 的共同数学结构，以及密度、Alpha 和覆盖率为什么不是同一个量。

验收：CPU 参考实现渲染一个解析密度球；打印一条射线的每步 `sigma/alpha/T/weight`，验证所有权重非负且权重和不超过 1；改变步长后结果按预期收敛。

### G.2 CUDA 稠密体数据 Ray Marcher

把三维标量场放入 CUDA array/texture object，利用硬件三线性采样；每个 CUDA 线程负责一个输出像素，完成射线与包围盒求交、固定步长采样、transfer function、front-to-back 合成和 early termination。输出写入与 D3D12 共享的二维纹理，再由全屏三角形显示。

验收：RTX 5070 / `sm_120` 真机输出可重复图像；CUDA 与 CPU 小分辨率参考结果在给定误差内一致；compute-sanitizer 无越界或同步错误；窗口 resize 后共享纹理和描述符正确重建。

### G.3 体渲染质量与性能

研究采样步长、抖动、预乘 Alpha、数值稳定性、early termination、空空间跳过、occupancy grid 和分块加载；使用 Nsight Compute 判断采样器、显存带宽、分支发散或计算吞吐哪个是实际瓶颈。区分“减少采样数量”和“提高单次采样吞吐”两类优化。

验收：在固定相机和数据集上比较至少三种步长及开启/关闭跳空的误差和 GPU 时间；报告平均采样次数、提前终止比例和关键 profiler 指标。

### G.4 NeRF 的数据与表示

学习相机内参/外参、像素射线、位置编码，以及 `F(position, direction) -> (sigma, rgb)` 的含义；从训练图像采样射线，通过 G.1 的可微体渲染得到预测颜色并计算损失。明确训练、推理、场景表示和最终渲染是四个不同环节。

验收：用小型 PyTorch 基线对一个极小场景完成前向、反向和过拟合测试；检查射线方向、坐标系和矩阵约定，避免把 OpenGL、COLMAP 和当前 D3D12 相机坐标直接混用。

### G.5 NeRF 采样与实时化路径

学习分层/重要性采样、coarse/fine 网络、occupancy grid、Instant-NGP 多分辨率哈希编码、混合精度和批量 MLP 推理。分析哪些成本来自场表示查询，哪些来自射线采样与合成；需要高性能训练/推理时使用 tiny-cuda-nn 等成熟实现，并把关键布局和算子与已学 CUDA 概念对应起来。

验收：同一场景比较朴素位置编码基线与一种加速路径的训练/推理时间、显存和图像误差；D3D12 只消费已经定义清楚的输出纹理，不把框架内部张量生命周期含糊地称为“直接共享”。

### G.6 3DGS 数据模型与投影数学

学习每个高斯的三维均值、尺度、旋转、协方差、不透明度和球谐颜色；由尺度与旋转构造半正定三维协方差，再通过相机变换和投影 Jacobian 得到屏幕空间二维协方差/椭圆包围范围。解释球谐函数提供视角相关颜色，而不是几何变换。

验收：CPU 与 CUDA 分别投影一小组已知高斯，比较屏幕中心、深度、二维协方差和包围矩形；过滤相机后方、退化或超大高斯，并记录过滤原因。

### G.7 3DGS 分桶与排序管线

实现视锥裁剪、每高斯覆盖 tile 数量计算、prefix sum 分配、按 tile 复制引用、生成 `tileId + depth` 排序键、radix sort 和 tile range 构建。复用 CUB 的 scan/sort，而不是手写通用排序；逐阶段说明临时存储、计数上界、溢出检查和 CUDA stream 依赖。

验收：小场景用 CPU 参考列表核对每个 tile 的高斯集合和深度顺序；大场景报告可见高斯数、重复引用数、临时显存和各阶段 GPU 时间；输入顺序打乱后结果保持一致。

### G.8 3DGS Tile Splat 光栅化

每个 CUDA block 负责一个屏幕 tile，批量把高斯参数载入 shared memory；每线程负责一个像素，计算二维高斯权重并按前到后顺序执行透射率/颜色累积和 early termination。明确这是一条专用的排序 Alpha 合成管线，不等同于“天然 OIT”，也不能直接套用普通网格的 BlendState 得到相同结果。

验收：与小分辨率 CPU splat 参考图比较；验证改变输入数组顺序但保持排序键不变时图像一致；compute-sanitizer 通过，并用 Nsight Compute 检查 shared memory、occupancy、分支和访存。

### G.9 NeRF/3DGS 训练系统与资产格式

在可信上游实现中学习可微渲染、反向梯度、优化器，以及 3DGS 的 densification、clone/split、prune 和 opacity reset；解析常见相机数据与 PLY 高斯属性，定义我们渲染器内部的版本化格式。重点理解训练如何产生可渲染参数，不要求从零重写完整自动微分框架。

验收：导入一个由参考实现训练得到的场景，逐字段验证高斯数量、位置、尺度、旋转、opacity 和 SH 阶数；未知或缺失属性给出明确错误，不静默猜测格式。

### G.10 与 D3D12 小型渲染器集成及对照评测

把体渲染、NeRF 输出和 3DGS 作为独立 Render Pass 接入现有渲染器，定义颜色/深度、线性/sRGB、预乘 Alpha、相机和 Fence 契约；研究它们与网格场景的遮挡和合成。以固定相机路径比较表示大小、加载时间、训练时间、渲染时间、显存、画质和动态编辑能力。

验收：同一个 D3D12 窗口可切换网格、体渲染和 3DGS 视图；所有跨 CUDA/D3D12 资源都具有明确生产者、消费者、External Fence 值和 D3D12 Resource State；最终报告不能只比较 FPS，还要记录分辨率、场景规模、误差指标和硬件环境。

## 9.1 阶段 H：PT 课程结束后的动态角色综合项目

独立实施文档：[H1–H7 动态角色路径追踪 Demo 实施计划](H阶段-动态角色路径追踪Demo实施计划.md)，包含资产候选、程序面积光方案、逐节验收和工程组织；规划不等于实现完成。

2026-10-20 学习者提出并纳入计划；2026-10-21按连续授权完成H1–H7教学实现与验收，详见[工程入口](sandbox/d3d12/dynamic-character/README.md)及[H7实测与边界](笔记/d3d12/H.7-整合验收与性能边界.md)。目标是在路径追踪场景中，让一个人物按我们定义的状态机自主移动、奔跑和跳跃；相机默认3D俯视透视视角，允许WASD平移和鼠标自由改变观察角度。角色决策与相机输入独立，不默认把WASD同时绑定给角色。

原始安排是在 PT 主线及计划内扩展完成后进入 H，不把全部 E/F/G 作为硬性前置；本轮已依此完成 H 的教学实现。下列各节保留学习目标与验收定义，实际范围见对应讲义和[当前进度](进度.md)。动态历史所需的时域概念与 F 相连；后续材质、降噪、水体和调度扩展统一进入 [V1–V7 应用路线](规划/渲染器后续优化路线.md)。继续执行共享主线、职责拆分、逐节 results 与笔记双向链接约定。

### H.1 角色资产与动画数据

使用成熟导入库导入一个骨架与兼容的Idle/Walk/Run/Jump动画片段；解释骨骼、绑定姿势、逆绑定矩阵、顶点骨骼索引/权重与动画轨道。先验证Assimp实际保留的信息、时间单位和坐标约定，不假定多格式导入自动解决重定向。优先采用同一骨架的资产，资产来源及许可在选择时确认。实现采用角色专用导入适配入口按已验证能力接收 Skin/Animation；C.6 静态导入入口继续保留拒绝保护，并执行静态资产回归，不因 H 可导入角色就宣称所有入口支持通用动画资产。

### H.2 动画采样与姿势混合

从时间采样局部平移、旋转、缩放，更新骨骼层级，构造蒙皮矩阵；CPU参考验证后再接入GPU蒙皮。实现循环播放、速度调整及短时姿势混合，区分动画片段时间和仿真时间。绑定姿势和已知关键帧作为数值验收。

### H.3 角色运动与状态机

自定义Idle→Walk/Run→Jump→Fall→Land→Idle/Run等状态与转换条件，状态机输出运动意图和动画参数。首版采用原地动画配合角色世界位移，讲明它与Root Motion的区别，避免重复位移。固定仿真步长下处理水平速度、重力、起跳速度与地面接触；先用平面/简单碰撞体，不把NavMesh、复杂物理、IK与动作重定向纳入首版。跳跃轨迹由运动逻辑决定，动画表现肢体姿势，落地由接触条件决定。

### H.4 俯视起始视角与自由相机

复用现有相机约定，默认俯视透视位置，WASD移动相机、鼠标调整yaw/pitch；明确移动所在平面、速度与时间步、俯仰限制、输入焦点和鼠标捕获/释放。提供恢复默认视角；角色状态机独立运行。固定俯视不限制后续自由观察角度。

### H.5 动态角色接入DXR

本轮 GPU 蒙皮更新位置与法线，让加速结构和命中着色读取同一帧几何。原始规划中的切线属性尚未实现，随 [V3 材质与法线贴图](规划/渲染器后续优化路线.md)扩展，不计入 H.5 已完成范围。区分骨骼导致的局部网格变形与角色整体世界变换；分别处理动态BLAS与TLAS，比较满足条件时的更新与重建。讲清资源状态、UAV依赖、构建标志、帧资源和Fence；静态环境复用静态资源。验收角色姿势、阴影和反射一致，无上一帧几何残留。

### H.6 动态路径追踪与历史有效性

角色或相机持续变化时不能沿用静态场景的无限跨帧平均。先用场景变化重置历史建立正确基线，接受运动期间低采样噪声；再实现所需的运动矢量/前帧变形位置、重投影、深度/法线与遮挡变化拒绝、受控时域降噪。动画暂停且相机静止时恢复静态收敛。比较干净逐帧参考、简单重置与时域处理，说明时域滤波的偏差，不将降噪称为额外真实样本。

### H.7 综合验收与性能预算

单人物在路径追踪场景中按可重复状态序列行走、奔跑、起跳、下落和落地，自由相机可在运行中移动旋转；验证动画切换、接触、阴影/反射、历史失效、暂停恢复和资源同步。记录RTX5070上的分辨率、spp、反弹数、蒙皮/AS/追踪/降噪耗时与显存，基于实测选择交互档和静止高质量档，不预先承诺特定分辨率下60FPS或无噪声。

## 10. 最终项目验收

最终项目不以“能显示一个三角形”作为完成标准，而以以下清单为准：

- 能加载一个 `.gltf` 和一个 `.glb`，并验证二者内部数据一致。
- 能绘制多 primitive、多 node、索引网格和至少一种纹理材质。
- CPU 正确构造 Model/View/Projection；shader 只应用上传矩阵。
- 深度测试、viewport/scissor、资源状态和 descriptor 绑定正确。
- 解析器对不支持的扩展明确报告，不静默产生错误几何。
- D3D12 Debug Layer 无未处理错误；CUDA 路径通过 compute-sanitizer 相关检查。
- CUDA 可选地更新实例或动态顶点数据；同步不依赖每帧 CPU 阻塞。
- 文档包含数据流图、资源所有权图、Fence 时间线、构建命令、测试结果和已知限制。
- PT 附加课程完成后，能从渲染方程推导路径权重，解释 NEE/MIS/俄罗斯轮盘赌，运行 CPU
  参考与 CUDA 路径追踪器，并以误差和 profiler 数据验证 BVH、Megakernel/Wavefront。
- 能说明 ReSTIR reservoir 复用为什么能降方差、何时引入偏差；能区分 UE5 Lumen、
  UE5 Path Tracer 和 NVIDIA NRC，不把三者说成同一个系统。
- 附加课程完成后，能用同一场景比较 No AA、MSAA、FXAA、TAA 和至少一个官方超分 SDK，并说明质量、成本、输入需求和失效场景。
- G 附加课程完成后，能解释体渲染、NeRF 和 3DGS 的表示与渲染差异，运行教学版 CUDA 体渲染和 3DGS 前向渲染器，并用可重复数据比较正确性、性能和显存成本。
