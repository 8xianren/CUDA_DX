# 小型渲染器后续优化路线

规划日期：2026-10-21。状态：**待实施的应用迭代计划**。本文不把计划当作完成记录，也不修改 H1–H7 的课程验收状态。

工程入口：[dynamic-character](../sandbox/d3d12/dynamic-character/README.md)；模块边界：[ARCHITECTURE](../sandbox/d3d12/dynamic-character/ARCHITECTURE.md)；完整课程：[学习计划](../学习计划.md)；当前证据：[H7 画质修正](../笔记/d3d12/H.7-画质修正与程序天空.md)。

## 1. 我们要把它完善成什么

目标是一个能配置场景、灯光、材质和画质，能稳定展示动态角色与水面的模块化 DXR 路径追踪器。画质提升要同时照顾四件事：照明是否正确、资产是否有细节、运动是否清晰稳定、运行成本是否可接受。增加光源和水面会增加新路径与噪声，必须与采样、降噪、资源调度一起推进。

本文的 **V1–V7 是 H 项目后续应用迭代编号**，不是既有课程新增的完成章号。F 仍负责抗锯齿、时域重建和超分的系统教学，G 仍负责体渲染、NeRF 和 3DGS。遇到相同内容时，学习原课程、实现一份公共模块，再接入这个 Demo，不重复建设第二套技术主线。

## 2. 当前能力与真正缺口

下面依据实际源码与已保存结果区分现有能力和新增工作，避免把已经做过的内容重新包装成任务。

| 方向 | 当前确实存在 | 后续要补什么 |
|---|---|---|
| 分辨率与采样 | 默认内部 1280×720，动态 4 spp、6 次散射，暂停每帧 16 spp；JSON 可改分辨率 | 明确内部/输出尺寸；运行时质量档、动态分辨率、可靠的放大与历史重建 |
| 天空与太阳 | 程序天空与有限角度太阳，参与主射线、直接采样、反射和间接光 | HDRI 载入与重要性采样、可编辑太阳、背景与照明联动；物理大气属于更后面的选项 |
| 局部灯光 | `PathLight` 三角形灯数组与世界面积 CDF，支持多个发光三角形；当前主要用程序面光 | 统一点光、聚光、面光、太阳、环境光数据；可编辑多灯；按能量/位置改进选灯 |
| 材质 | 金属/粗糙度 PBR、平滑顶点法线、共享材质纹理基础；人物和装饰有演示覆盖参数 | 完整切线空间法线、Mip/LOD、双面和 alpha-mask 植被、材质编辑、资产质量 |
| 玻璃基础 | PT.8 共享积分器有封闭、非嵌套、无吸收的平滑玻璃教学路径；由材质名覆盖 IOR | 正式介质参数、进出边界、吸收和实际厚度，之后再做水面波动 |
| 动态历史 | 变形网格上一帧重投影、几何拒绝、3×3 颜色限制、最多 8 帧历史 | 漫反射/高光拆分、显露处理、方差引导空间滤波、反射与折射历史；不能只加大历史权重 |
| 动态反射 | 路径能追踪反射；高金属/低粗糙度区域当前主动拒绝历史 | 降低反射噪声，并处理反射画面与表面运动不一致的问题 |
| GPU 调度 | CUDA 蒙皮、共享缓冲与 Fence、动态 BLAS 更新、TLAS、阶段计时 | 跳过不变更新、资源池、多帧资源、异步读回、回收策略、按测量决定更新/重建 |
| 应用工具 | 双击启动、JSON、相机、暂停/单步、固定回放与验收脚本 | 运行时面板、场景预设、灯光与材质调节、诊断图、图像序列导出 |

源码定位：[帧契约](../sandbox/d3d12/dynamic-character/src/render/frame.h)、[渲染调度](../sandbox/d3d12/dynamic-character/src/render/dxr/renderer.cpp)、[灯光表](../sandbox/path_tracing/dxr-path-tracer/path_scene.h)、[路径积分](../sandbox/path_tracing/dxr-path-tracer/path_integrator.hlsl)、[程序天空](../sandbox/path_tracing/dxr-path-tracer/sky_environment.hlsli)、[当前时域滤波](../sandbox/d3d12/dynamic-character/shaders/temporal.hlsl)。

目前 720p/1080p 动态档的离屏整帧中位数约为 11.18/17.63 ms，来自已有 `results/visual/performance.csv`，**不含窗口 Present，不能当成端到端帧率承诺**。同一 720p 动作末帧对 256 spp 参考的线性 MSE 从 0.00138809 降至 0.000176752；这只证明该测试场景降低误差，不能证明所有镜头都清晰或没有拖影。

## 3. 实施顺序与交付

P0 表示先建立正确性和可比较的画质基线，P1 表示主要表现提升，P2 表示在依赖满足后扩展。没有预先保证某项会提升多少 FPS；每项都保存可复现对照。

| 迭代 | 优先级 | 前置依赖 | 能交付什么 | 主要验收 |
|---|---|---|---|---|
| V1 画质基线与清晰度 | P0 | 当前 H7 | 固定镜头/动作、原生分辨率对照、颜色流程和质量预设 | 静态细节裁剪图 + 动态序列 + 同预算指标 |
| V2 统一灯光与 HDRI | P0/P1 | V1 | 多灯展厅、日夜预设、可旋转 HDRI、统一光源采样接口 | 单灯求和、多灯高采样参考、PDF 与阴影检查 |
| V3 材质与资产 | P1 | V1；最终展示配合 V2 | 法线贴图、材质球场、双面裁剪植被、一套风格统一的场景 | 法线/UV 诊断、材质参数阶梯、近中远景对照 |
| V4 动态降噪与重建 | P0/P1 | V1；V2/V3 提供压力场景 | 漫反射/高光分离、显露处理、可切换降噪；对接 F 的重建接口 | 人物/阴影/反射运动序列，不以单帧平滑判断通过 |
| V5 水体 | P1；分 V5a/V5b | V2、V3；动态验收依赖 V4 | 先封闭静水池，再受控波浪和水面历史 | 折射与吸收数值参考、掠射反射、动态稳定性 |
| V6 GPU 调度与资源 | P1 | V1 指标；各阶段均可局部优化 | 持久资源池、按需 AS 更新、多帧槽与可核对 Fence 时间线 | 同输入同图像，端到端/分阶段 p50/p95、显存与长跑 |
| V7 场景与调试工具 | P1/P2 | V1；随 V2–V6 增量接入 | 场景/灯光/材质/画质面板、预设与回放、可搬运运行包 | 保存重载一致、错误回退、打包后独立启动 |

推荐先做 **V1 → V2 → V3 → V4 → V5a → V5b**。V6 中“消除每帧分配、跳过不变工作”和 V7 的最小调参面板可穿插；多帧并行等同步结构改动单独验收，避免同时改变积分器和队列模型而无法定位差异。

## 4. V1：先弄清楚为什么糊

“糊”可能来自内部像素不足、放大过滤、历史融合、纹理 LOD，也可能只是素材没有细节。先把这些因素分开，而不是直接加锐化。

**交付：** 固定日间场景、室内灯光场景和角色绕行回放；统一导出原始线性图、显示变换图、运动序列和配置。先建立 720p 原生、1080p 原生、低内部尺寸放大三组对照，同时显示真实内部/输出尺寸与 spp。

1. 对照原始 PT、当前历史、暂停高采样；保留太阳高光、人物轮廓、远处树叶、地面纹理四种 100% 像素裁剪，禁止为对比图使用不同缩放或曝光。
2. 将纹理解码、线性积分、曝光、显示变换分清。曝光变化属于显示操作，不重算路径；照明/材质变化则有历史失效规则。
3. 保留当前显示变换作为基线，增加显式可选的显示方案；固定白平衡、曝光和输出色域后再判断材质。若采用 ACES，核对输入色域及完整输出变换，不能把一条近似曲线叫作完整 ACES 流程。官方对输出变换的定义见 [ACES 文档](https://docs.acescentral.com/system-components/output-transforms/)。
4. 建立“交互、画质、静态参考”预设。参考图至少使用两个独立随机种子，检查提高样本数后参考本身是否已稳定；256 spp 不是所有场景都足够的真值。

**通过标准：** 每张图能追溯相机、资产哈希、随机种子、样本数、散射上限、内部/输出尺寸和曝光；平面斜边、棋盘与细线在原生尺寸下没有额外缩放；线性黑/灰/亮度阶梯数值通过；不以锐化光晕冒充真实细节。

**模块：** `app` 管理预设与回放；`render` 输出诊断和线性结果；显示 Pass 管理曝光与色调，不把 UI 参数读取塞进积分器。

## 5. V2：统一灯光、多光源与环境

### V2a 灯光数据与编辑

建立项目自有 `LightDesc`、稳定灯 ID、类型、变换、颜色、强度与单位、形状、可见性、版本号。CPU 场景保存语义数据；渲染后端生成紧凑 GPU 表和采样分布。材质发光与可采样光源记录保持映射，灯光移位、尺寸变化后更新世界几何与分布。

逐项接入点光、聚光、矩形/圆盘或三角形面积光、太阳和环境光。点光无几何面积；有柔和阴影需求时使用真实有限面积光，不给 delta 点光随意混入面积 PDF。太阳的方向、颜色、角半径分别可调。明确“固定辐亮度时放大面积”与“固定总功率时放大面积”的不同，编辑器给出参数单位。

导入 glTF `KHR_lights_punctual` 时遵守 directional/point/spot 的定义和单位；矩形面光、HDRI 并不属于这个扩展，使用明确的项目场景描述。依据：[Khronos 光源扩展](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_lights_punctual/README.md)。

### V2b 灯光选择与 MIS

现有三角形面积 CDF 已能处理多个发光三角形；新增的是灯类型统一和高效选择策略。先实现均匀选灯作为参考，再按功率构建 CDF/alias 表。在所有可能贡献的灯上保留非零选择概率。对非 delta 灯，记录完整密度：

```text
p_light(ω) = P(选择灯 i) × p(方向 ω | 灯 i)
```

面积 PDF 必须转换到同一立体角测度，再与 BSDF PDF 计算 MIS。BSDF 路径撞到发光面或逃逸到环境时也能查询对应灯的完整密度，避免重复计光；delta 灯走明确的离散处理。原理依据：[PBRT 灯光选择](https://www.pbr-book.org/4ed/Light_Sources/Light_Sampling)、[光源接口](https://www.pbr-book.org/4ed/Light_Sources/Light_Interface)。

小灯数量从 1、4、16 扩至 64 做标定。只有确认全局功率选灯浪费明显后，才评估空间灯光树或复用已有 PT.11 的 reservoir 思路。ReSTIR 的接入必须重新验证动态可见性和目标函数，不能把过去小实验直接称为动态场景方案。

### V2c HDRI 与天空

载入线性 HDR 环境图，保留来源、许可、旋转和强度；经纬图重要性分布考虑亮度与球面面积权重，处理极点、接缝和全黑图。环境亮区同时影响背景、反射与照明，主射线/Miss 和 NEE 使用同一环境定义。先限制为一种活动环境，再开放明确叠加模式，防止 HDRI 中已有太阳却又叠加一颗独立太阳而无意重复能量。参考：[PBRT 环境光](https://pbr-book.org/4ed/Light_Sources/Infinite_Area_Lights)。

**交付画面：** 日间户外、傍晚暖灯、暗室多彩灯三套可切换预设；同一金属球可观察环境反射随 HDRI 旋转，人物阴影随灯位置与面积变化。

**通过标准：** 固定相机下多灯图的均值与单灯分开渲染再求和一致（统计容差由多随机种子给出）；灯强加倍线性响应；全关灯黑图；灯后遮挡物不产生错误阴影；不同选灯策略收敛到相同均值。记录每路径阴影射线数量、采样/追踪耗时、等时间噪声和显存，不要求每像素每反弹遍历全部灯。

## 6. V3：材质和资产质量

**先补材质输入，再换更复杂资产。** PT 只能根据输入几何、法线和材料分布计算光输运；低细节模型不会因提高 spp 自动变成写实模型。

1. 保留原始导入材质与展示覆盖参数两层，支持选择恢复原始参数；不要在导入时永久把所有物体改为同一粗糙度。
2. 加入切线及其手性，建立 TBN，正确解码法线纹理；骨骼变形同时处理需要的法线/切线并重新正交化。区分几何法线（边界、偏移、正反面判断）与着色法线（BSDF），加入背向与能量异常诊断。
3. 明确 baseColor/emissive 与 normal/metallic/roughness 等纹理的颜色空间；生成或载入 Mip。射线纹理 LOD 先给出可解释基线，再评估 ray cone 等足迹估计，避免远处闪烁和过度模糊。
4. 加入不透明、alpha-mask、双面材质的独立语义。主射线和阴影射线对裁剪孔洞一致；双面薄叶片不自动等于厚介质，也不等于体散射。薄片透射作为后续单独材质扩展。
5. 增加质量较好的地面、石头、树木与一个人物，统一单位、色调与风格；先导入少量资产进行覆盖测试。资源保存作者页面、许可、版本/下载日期、哈希；用代理资产保持自动验收稳定。

glTF 的纹理、材质和双面行为以 [glTF 2.0 官方规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) 为依据；具体扩展只在完整实现相关字段和失败行为后标为支持。

**交付画面：** 粗糙度×金属度材质球阵列、带法线贴图的岩石/地面、正反两面可见的裁剪叶片、近中远景同资产对照。

**通过标准：** 平法线图与无贴图对照一致；镜像 UV/负尺度/蒙皮后无翻转；远景纹理不靠错误低 LOD 显得“锐”；叶片裁剪和影子一致；材质白炉/能量旧测试仍过。记录纹理与切线显存、AnyHit 成本和不同 LOD 策略误差。

**模块：** `assets` 负责解析/校验；CPU 场景持有材质描述；`render` 管理 GPU 纹理与采样器；`animation` 输出姿势，GPU 蒙皮模块处理所需顶点属性，不让材质逻辑进入人物状态机。

## 7. V4：动态降噪、抗锯齿与重建

这是“动态画面更清晰”的核心工程，而不是把最大历史从 8 改成 64。表面运动只能告诉我们表面去了哪里，不能直接告诉我们镜中人物、移动阴影或水下折射去了哪里。

### V4a 信号与历史契约

输出独立 diffuse/specular 信号、线性深度、几何/着色法线、粗糙度、材质/实例 ID、运动向量、命中距离与置信度。信号名称、单位、坐标和是否包含曝光/jitter 逐项固定。当前中心主射线 guide 与抖动 beauty 的边缘覆盖差异必须处理，不能把不同表面的信号混到一条历史里。

显露区域（上一帧被挡住、这一帧刚出现）需要重建，不能从不存在的旧样本取颜色；相机切换、材质/灯光编辑、分辨率变化分别定义重置策略。天空使用方向重投影；背景不伪造有限深度。

### V4b 降噪算法与反射

先增加可检查的方差估计与边缘引导空间滤波，并保留当前方法和完全关闭降噪两个基线。分别调整 diffuse/specular 的历史权重、方差和滤波半径；镜面高光不沿用漫反射长历史。为反射运动研究命中距离、虚拟位置重投影和低置信度退回当前帧的策略。

若接入 NRD，作为 `render` 后处理模块适配输入，而不是改写人物/动画代码。按官方版本固定依赖并保存许可。NRD 对 normal、roughness、viewZ、motion 等信号有具体要求，透明和体积并非默认适用范围；水体不能只传入一张 beauty 就期待自动正确处理。依据：[NVIDIA NRD 文档](https://github.com/NVIDIA-RTX/NRD)。

### V4c 与 F 课程合流

F.4–F.6 教授并实现统一 jitter、运动矢量、TAA/分辨率契约，F.7–F.8 再集成一个正式超分 SDK。PT 自身用亚像素射线采样处理像素覆盖；MSAA 的光栅课程仍保留，但不把“给 DXR 加 4×MSAA”当成路径追踪抗锯齿方案。降噪、抗锯齿和超分分别可切换，避免多套长历史串联后再次糊化。

**交付序列：** 人物横穿树干、镜面中的跑跳人物、快速转相机、移动聚光灯、突然熄灯、草叶细线与天空边界，至少各 120 帧固定回放。

**通过标准：** 对同一回放逐帧生成高采样参考，比较运动区域与静态区域误差；保存拖影时间图、显露掩码、历史长度与锐度裁剪。数值误差下降但人物细节被抹掉时不算通过；Camera Cut/灯光编辑后无旧轮廓残留。记录重建成本与真实内部尺寸，原生 1080p 和重建 1080p 分开标注。

## 8. V5：水体按两个阶段实现

### V5a 静水池：先建立可信的介质边界

第一版使用封闭、非嵌套的浅水体：平水面、侧壁和池底定义清楚，镜头先在水外。复用已有平滑玻璃反射/折射基础，把 IOR 和介质参数从 `teaching_glass` 名称覆盖提升为正式材质字段。

跟踪射线当前所处介质，明确入水/出水、全反射和路径权重。Fresnel 决定随入射角变化的反射与透射；掠射角反光增强应由界面模型产生。依据：[PBRT 介电 BSDF](https://pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)。

增加均匀介质吸收系数 `σa`（单位 1/m），沿实际水内路径长度 `d` 衰减：`T = exp(-σa × d)`。池底越深、斜射路径越长，透射颜色应相应变化；不使用任意屏幕深度差冒充折射后的真实路程。第一版不含体散射与水下光束。依据：[PBRT 透射率](https://www.pbr-book.org/4ed/Volume_Scattering/Transmittance)。

同时明确阴影射线的适用条件：水内不跨折射边界的线段可乘介质透射率；穿过折射界面连接灯光时，不能简单沿原直线“忽略水面并乘透明度”冒充正确光路。首版保留正确的界面路径采样及其噪声边界，采用宽环境/大面光完成基线；小太阳经折射在池底聚光的问题单独记录，不用任意照亮池底的补丁掩盖。

glTF 的 [transmission](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_transmission/README.md) 与 [volume](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_volume/README.md) 提供表面透射与体属性表达；实际光追厚度、资产厚度参数和薄片模型不能混为同一含义。导入支持单独验收，首版可先用明确的程序介质描述。

**交付画面：** 棋盘池底、浅深两个台阶、半浸入物体、掠射角天空反射；水深与吸收系数可调。

**通过标准：** 折射方向与 CPU 双精度 Snell 参考一致；吸收为零恢复透明基线；同色均匀水体路径长度加倍满足 `T(2d)=T(d)²`；检查全反射、出入边界、自相交、相机入水后的介质初始化。以独立高样本参考检查均值，不能仅凭“蓝色且透明”通过。

### V5b 波浪：几何、照明与历史一起变

从少数解析正弦/Gerstner 波开始，以固定时间生成位移与解析导数法线；先限制幅度/陡峭度，避免折叠和破坏封闭水体。较大波浪写入真实网格并更新水体 BLAS，细小纹理起伏只改变着色法线；两者在轮廓、遮挡和反射上的能力不同。

为水面保存上一帧位移，提供水表面的运动；同时保留反射/折射信号低置信度回退，因为水表面运动并不覆盖水下景物运动。将其加入 V4 的高光/透明历史压力测试。

**交付序列：** 同一浅水池从静水过渡至小幅波浪，相机绕行，人物从池边经过；比较无历史、受控历史、高采样参考。

**通过标准：** 停止时间时位移和历史稳定；解析导数与有限差分法线吻合；BLAS 更新与重建图像一致；波纹/反射没有长期拖尾；记录网格密度、更新成本、追踪成本与历史拒绝比例。

**明确后续选项：** FFT 海洋、交互流体、泡沫、岸线湿润、体散射与焦散均不属于首版水池。小光源经镜面折射形成的焦散对普通相机路径采样困难，应单列算法和参考验证，不能承诺“加折射后自动得到稳定焦散”。体积雾和水下散射与 G.1–G.3 合流，不提前复制体渲染器。

**模块：** `simulation` 或独立水面运动模块生成时间参数/形变；`assets` 定义水体网格和介质；`render` 实现 BSDF/介质积分、AS 与历史。人物控制继续只输出人物状态。

## 9. V6：GPU 调度与资源管理

先消除可证明的重复工作，再增加并发。

1. 记录角色姿势、实例变换、灯光、材质、相机的独立版本。暂停且姿势不变时跳过 CUDA 蒙皮与对应 BLAS；仅刚体移动时更新实例/TLAS；相机移动不要求重建几何。
2. 将 TLAS 实例、scratch、常量上传、描述符、历史与读回缓存改为可复用资源，统计每帧分配次数。静态 BLAS 可评估压缩；动态 BLAS 分别测 UPDATE/周期性 REBUILD 的构建与后续追踪总成本。
3. 复用 E.3 学过的帧槽和 Fence 思路，给每槽 palette、变形顶点、AS、临时缓存建立所有权；历史资源按其独立跨帧依赖管理。只删除已经由 GPU 依赖替代的 CPU 等待，不能直接去掉 `SubmitWait`。
4. 定时结果延迟读回，截图才读回颜色；窗口 Present、CPU 等待、CUDA、AS、PT、降噪分别计时。引入异步队列前检查实际时间线，跨 API 不自动意味着硬件重叠。
5. LOD/实例分组不能只看主相机可见性。视野外人物和树木仍可能投影、反射或间接贡献；剔除策略必须说明保守条件与画面损失。

规范依据：[Microsoft DXR 规范](https://microsoft.github.io/DirectX-Specs/d3d/Raytracing.html)。更新/重建选择与长期形变后的遍历效率需要实测，可参考 [NVIDIA 网格与加速结构建议](https://developer.nvidia.com/blog/creating-optimal-meshes-for-ray-tracing/) 和 [AS 压缩流程](https://developer.nvidia.com/blog/tips-acceleration-structure-compaction)。

**交付：** 单槽基线和多槽实现的同场景对照、资源占用图、Fence 时间线、10 分钟连续运行记录。

**通过标准：** 固定随机种子与回放输出一致（或解释并审计浮点容差）；无跨槽写读竞争、resize 后悬空资源或显存持续增长；报告端到端 p50/p95、GPU 各阶段、CPU 等待、峰值显存、预热与测量条件。Nsight Compute 剩余硬件计数器分析沿用用户此前暂缓决定，不把它变成本轮优化前置条件。

## 10. V7：场景、调参和展示工具

先做最小面板：场景预设、相机书签、灯类型/强度/尺寸、HDRI 旋转、材质 roughness/metallic、分辨率/spp/散射上限、降噪开关与统计。UI 发编辑命令，App 更新场景描述与版本号；渲染器消费快照，不能反向操作玩家输入。

增加法线、深度、运动向量、材质 ID、光源 PDF、历史长度、显露、路径异常等诊断视图。保存/读取 JSON 预设时带格式版本、字段验证和相对路径规则，加载失败保留原场景并给出具体错误。录制相机与动作回放，输出图像序列和配置清单。

随后整理场景层次、选择/移动物体、资源统计与基础 hot reload。Shader/材质热更新使用新资源完整创建后替换，旧资源等待 Fence 退役；编译失败保留上个可用版本。资产质量、灯光布局和摄影构图同技术验证一起迭代。

**交付：** 用户无需改 C++ 即可保存“晴天水池”“傍晚多灯”“材质检查”三个场景，换目录启动可复现；参数实时变化有清楚的历史处理行为。

**通过标准：** 保存重载前后同种子同图像；坏参数、丢失素材、Shader 编译失败能解释并回退；UI 按输出分辨率显示而不随内部比例变糊；测试配置与用户预设分离。人物直接控制、碰撞/跟拍是应用玩法迭代，可独立加入，不以它们替代画质优化。

## 11. 每次迭代都要留下的资料

实现继续复用 `learning/sandbox/d3d12/dynamic-character/` 的模块，公共 PT 改动保留在原共享主线；不为 V1、V2 等复制完整工程。新增结果分别归入该工程的 `results/v1/`、`results/v2/` 等目录，课程关联讲义仍放 `learning/笔记/<线路>/` 并双向链接。这里的目录名是后续约定，目前不表示目录和功能已创建。

每次交付包括：一段用户可直接操作的场景、对应讲义/设计说明、构建与运行命令、带参数的前后图或帧序列、独立参考或负对照、性能/显存结果、尚未支持的明确边界。新的大章可拆成 V2a/V2b 等小节，但不省略学习者要求的推导、API 参数、布局、所有权与同步讲解。

优先提升顺序是：**可解释的画质基线 → 可控光照 → 材质与资产细节 → 动态稳定性 → 静水与波浪 → 调度和工具成熟度**。高质量最终画面由这些部分共同决定，某一张漂亮静帧或某个高 FPS 数字都不能独自代表渲染器完成。
