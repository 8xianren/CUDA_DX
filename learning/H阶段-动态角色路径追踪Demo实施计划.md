## 1. 最终场景与范围

制作一个小型林间训练场：中央空地供一个人物自主行走、奔跑、起跳、下落和落地；周围摆放少量静态树木、石头和灌木。加入粗糙度不同的测试物体和可辨识角色反射的表面，检查动态几何在主视图、阴影与反射中的一致性。

相机默认斜俯视透视视角，WASD 移动相机，鼠标改变观察方向。人物由独立状态机驱动，不把相机输入同时用于人物运动。提供动画暂停、固定仿真单步、恢复默认相机及调试显示。人物、相机与灯光静止后进入渐进收敛模式。

首版采用低面数、风格化资产，树冠优先实体网格。暂不加入 NavMesh、复杂物理、脚部 IK、通用动作重定向、布料或头发模拟。资产数量、分辨率与采样预算在实际运行后调整，不承诺特定分辨率下 60 FPS。

## 2. 光源方案：程序定义照明，模型负责外观

场景需要发出能量的光源。石头、树木和普通人物材质只反射入射光，不能依靠曝光把完全没有入射光的场景变亮。灯具模型不是必要条件：程序可以直接生成发光几何并设置发光参数。下载的灯具外壳也不会自动成为有效光源，仍需正确解析或指定发光材质并接入积分器。

### 2.1 首版基线

- 在场景上方偏侧方放置一块朝向训练场的矩形面积光，由两个发光三角形构成，优先复用已有发光三角形 NEE/MIS 路径。
- 将它理解成可控摄影棚灯板。它能形成软阴影，便于观察角色接触和肢体运动；这是首版照明基线，不把有限距离灯板称作物理太阳。
- 首版使用黑色环境；暗部主要来自场景表面之间的间接反弹。若确需补光，可增加第二块较弱的面积光，并重新评估多灯采样和性能。
- 首版灯板作为真实几何参与相机、反射和遮挡，不默认隐藏它；“相机不可见但仍照明”属于需要明确射线可见性规则的额外功能。
- 地面、人物和树木沿用明确的材质参数，先保证灯光、材质和曝光分工清晰，再做美术调整。

### 2.2 数据与采样约定

场景配置保存灯光中心、方向/局部基向量、宽高、线性 RGB 发射辐亮度、是否启用，以及照明版本号。首版采用单面发光，明确正面法线。正面积和非负有限发光值必须检查；关闭灯光应从采样集合中移除或按一致规则处理零功率，避免除零。

宽高改变会同时影响面积、软阴影及总发射功率。若保持辐亮度不变，增大面积不是只改变阴影软硬；若需要固定总功率比较，应显式调整辐亮度并记录比较条件。参数暂不随意标为流明/坎德拉，除非已经完成对应的单位和光谱/光度转换定义。

发光几何既要能被路径命中，也要进入直接光采样列表。NEE 表示主动抽取光源样本；MIS 表示将光源采样和材质方向采样按各自概率密度组合，避免重复计数。复用已有实现时仍需核对三角形选择概率、面积到立体角的转换、单面发光、阴影射线范围和发光命中权重。

灯光强度/位置/尺寸变化会改变被积函数，必须更新照明版本并使相关历史失效；灯板变换还要更新相应场景几何和加速结构。曝光属于显示变换，单独调曝光不应重置线性辐亮度累积。

### 2.3 光照验收

1. 黑色环境、关闭全部发光体后，排除调试覆盖层的线性渲染结果应为黑。
2. 在线性、未色调映射结果中，将唯一光源辐亮度加倍，与相同采样序列的基线比较，应在数值容差内得到两倍结果；排除会破坏线性的限幅处理。
3. 加入遮挡物后，直接光可见性与参考一致；人物脚下阴影随接触、起跳和落地变化。
4. 小型已知几何场景验证单面朝向、光源后方物体不错误遮挡有限阴影射线，以及光源采样与发光命中的 MIS 一致性。
5. 灯光变化触发历史失效，曝光变化不改变线性历史；动画人物在阴影和反射中使用与主视图相同帧的几何。

### 2.4 后续室外照明选项

基线通过后可评估太阳方向光、天空模型或 HDRI 环境照明。HDRI 不是显示一张背景图就完成接入：还需要方向映射、环境辐亮度查询、采样概率与 MIS。环境贴图旋转或更换也影响历史有效性。该项作为可选扩展，不阻塞 H1–H7 核心验收；如纳入，应追加独立验收与性能预算。

## 4. H1–H7 实施与验收

| 阶段 | 具体工作 | 通过条件 |
|---|---|---|
| H1 资产与数据 | 导入一个角色、配套片段与少量装饰；核对 Assimp 的骨骼、逆绑定矩阵、权重、轨道、时间单位和坐标；确定场景尺度与灯光配置格式。 | 资产清单和数据报告齐全；绑定姿势正确；坏输入有明确诊断；按已实现能力放开 Skin/Animation 限制，静态导入回归通过。 |
| H2 动画与蒙皮 | CPU 采样局部 TRS、更新层级与蒙皮矩阵；循环、调速、短时混合；计划由 CUDA 写入供 D3D12 使用的变形顶点。 | 指定时刻、绑定姿势、循环边界和混合端点通过；GPU 位置/法线与 CPU 参考一致；权重和骨骼索引越界检查通过。 |
| H3 运动与状态机 | Idle/Walk/Run/Jump/Fall/Land；固定步长、重力、起跳和简单接触；原地动画配合世界位移。 | 可重复状态序列；相同固定步数下结果不受渲染帧率影响；不重复应用根位移；落地由接触条件决定。 |
| H4 相机与交互 | 俯视起始视角、WASD/鼠标、焦点和捕获处理、恢复默认视角、暂停/单步。 | 相机与角色决策独立；失焦不持续移动；resize、最小化和恢复正常；移动速度与时间步关系正确。 |
| H5 动态 DXR 与灯光 | 蒙皮几何接入动态 BLAS，角色世界变换接入 TLAS；比较更新与重建；接入程序生成的面积光和静态环境。 | CPU/射线参考、更新/重建对照通过；姿势、阴影、反射同帧一致；资源状态、UAV 依赖、跨 API Fence 与帧槽复用正确；光照基线通过。 |
| H6 动态历史 | 先做变化即重置，再做前帧变形位置、运动信息、重投影、遮挡/深度/法线历史拒绝及受控时域滤波。 | 相机、人物、灯光变化与显露区域有逐帧参考；噪声、拖影和偏差分别度量；暂停后恢复收敛。 |
| H7 综合验收 | 完成布景、运行入口、固定演示序列和配置；量化 RTX 5070 性能，选择交互与静止质量档。 | 完成功能、数值、图像、持续运行和窗口操作验收；记录耗时分布、显存与输入/构建版本；提供复现命令和结果。 |

H2 结束交付动画查看器；H5 结束交付采用历史重置基线的动态路径追踪场景；H7 结束交付完整 demo。每个节点保留可运行入口，不等待最后才集成。

## 5. 工程组织与已有能力复用

2026-10-21 用户补充明确要求：以模块化小型渲染器组织，而非把课程实验拼成一个大 main。渲染（DXR PT）、角色运动/状态机、动画、玩家输入分别拥有清晰边界，应用层负责组合；自主行为与玩家输入通过同一种角色意图接口接入。具体目录、依赖、帧数据契约和资源所有权见[架构文档](sandbox/d3d12/dynamic-character/ARCHITECTURE.md)。输入不直接操作骨骼/GPU，动画不负责物理接触，渲染不决定角色行为。

拟采用共享主线 `learning/sandbox/d3d12/dynamic-character/`，具体接入点在 H1 实现前检查现有索引与构建系统。按职责划分 assets/导入、animation、simulation、camera、render、shaders 和验证脚本；不为七节复制七套渲染器，也不将全部逻辑堆进单个源文件。

复用已有 glTF 导入、DXR 积分器、窗口/显示以及 E 章 CUDA/D3D12 互操作经验。E2 的简单位置形变不是完整蒙皮，E3 的有限批次槽位测试不是完整交互帧调度，已有静态降噪也不是时域历史管理，这些差距分别在 H2/H5/H6 补齐。

各节输出放入本主线 `results/h1` 至 `results/h7`；讲义放在 `learning/笔记/d3d12/`，与代码 README 双向链接。新增教学代码用详细简体中文注释说明布局、所有权、数学和同步。构建面向 RTX 5070 / sm_120，并沿用或接入现有构建入口。

## 6. 性能与完成判据

正确性和性能分开运行。正确性开启必要验证，性能记录验证层状态、预热、测量次数、Present/VSync、窗口/内部渲染尺寸和暂停状态。记录 CPU 仿真/动画开销、GPU 蒙皮、BLAS/TLAS、路径追踪、降噪、显示及整帧耗时；有重叠时不得简单相加各段时间充当整帧时间。

记录 spp、反弹数、三角形/实例数量、动画角色规模、灯光数量、显存与帧时间分布。以固定种子和固定仿真序列支持复现，以独立高采样逐帧参考评估质量。时域滤波可能带来偏差，不把历史混合称为增加真实独立样本。

延续用户此前授权：不将 Nsight Compute 硬件计数器作为阻塞项，不虚构缓存命中率等硬件归因。性能结论以实际完成的计时、图像对照和可用时间线证据为准。

完成时同步总计划、目录索引与学习进度；只有实际通过验收的课节才能勾选完成。本文件是实施计划，不代表资产下载、代码实现或性能目标已经完成。

## 8. 同日后续画质修正与下一轮范围

首轮功能验收后，按学习者反馈提高默认内部尺寸至 1280×720、动态 4 spp/6 次散射，暂停以每批 16 spp 继续累积；加入平滑顶点法线、参与照明的程序天空与有限角度太阳，并调整布景和角色路线。新图像、动态/静态参考及性能条件见[H7 画质修正与程序天空](笔记/d3d12/H.7-画质修正与程序天空.md)。首轮黑环境小尺寸数字不能当作新版默认场景的性能。

当前仍保留单帧同步、平面接触、受限时域滤波等边界；未实现切线空间法线贴图、通用介质/水体或生产级反射历史。切线/法线贴图、多灯与 HDRI、水体、动态降噪和多帧资源分别进入[后续 V1–V7 优化路线](规划/渲染器后续优化路线.md)，计划不视为已经实现。
