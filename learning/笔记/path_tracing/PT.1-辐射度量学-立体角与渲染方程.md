## 2. 先把三个容易混的词拆开

```text
光线追踪 Ray Tracing
    = 用射线做可见性 / 求交的一大类方法
    光栅化的阴影射线、反射探针、硬件 DXR 都算

路径追踪 Path Tracing
    = 用随机路径 + 蒙特卡洛，去估计渲染方程的一种光线追踪算法

DXR / OptiX
    = 加速结构、遍历、着色调度的 API
    不等于路径追踪本身
```

光栅化问的是：这个三角形投影到屏幕后，像素里填什么颜色。
路径追踪问的是：从相机出发的这条射线，沿路径收集到的辐亮度期望是多少。
两者最终都可能写入同一块线性 HDR 缓冲，再 tone map 成 sRGB；差别在积分器，
不在 Present。

UE5 里至少有两条不能互相替代的路径：

```text
Lumen            实时 GI / 反射。探针、Radiance Cache，可选硬件光追更新
UE Path Tracer   参考级渐进收敛，走 DXR + MIS
本课 PT.1–PT.10  可逐项验证的教学积分器，先 CPU 后 CUDA，不用 DXR 当黑盒
```

本节只需记住 **Lumen ≠ Path Tracer**。ReSTIR、NRC 放到 PT.11/PT.12。

## 3. 游戏开发类比：不要把“亮”当成同一种量

实时渲染里我们随口说 albedo、light color、NdotL、HDR。这些词对应不同的物理量。
把它们都叫“亮度”，单位会对不上，积分也会积错。

把一个点光源照一张桌子想成水管：

```text
Phi  通量        水龙头单位时间流出多少水         单位 W
I    辐射强度    某个方向的一束有多猛             单位 W/sr
E    辐照度      桌面上每平方米接到多少水         单位 W/m^2
L    辐亮度      从某个方向看，每平方米每球面度    单位 W/(m^2 sr)
f_r  BRDF        入射方向的能量，有多少被反射到出射方向   单位 1/sr
```

游戏里的对应关系（只作直觉，不是实现）：

```text
点光源的 candela / luminous intensity ≈ I 的光度学亲戚
方向光的 lux / 光照强度贴图            ≈ E
Shader 里看到的“表面颜色”             更接近 Lo，也就是辐亮度
albedo / baseColor                     更接近 ρ，无量纲反射率
Lambert 的 NdotL                       就是下面要讲的投影余弦
```

Photometry（光度学）是同一套几何，但按人眼 V(λ) 加权，单位变成 lumen、lux、nit。
渲染器内部积分必须用 Radiometry（辐射度量学）。Tone mapping、sRGB 编码是把线性
辐亮度变成显示器码值，那是 PT.10 的事。R.5.4 已经证明：文件里的 8-bit 颜色不是
线性能量。路径追踪全程在线性 HDR 里累加，不要提前做 gamma。

## 4. 四个辐射量，必须能互相换算

取一块面积 `dA`，法线 `n`，某个方向 `ω`，该方向与法线夹角 `θ`。

### 4.1 辐射通量 Φ —— 单位时间过某个面的能量

```text
Φ = dQ / dt          单位：W = J/s
```

它是最粗的量：整盏灯总共发出多少瓦。不问方向，不问落到哪一块面积。

### 4.2 辐射强度 I —— 通量对立体角的密度

点光源没有面积，不能谈辐照度，只能谈“朝某个方向的一束有多强”：

```text
I(ω) = dΦ / dω       单位：W/sr
```

各向同性点光源若总功率为 Φ，则 `I = Φ / 4π`，因为整球立体角是 `4π sr`。

### 4.3 辐照度 E —— 通量对面积的密度

桌面接收到的是辐照度：

```text
E = dΦ / dA          单位：W/m^2
```

同一盏灯，离得越近、面积越小、越正对，E 越大。这已经有面积，但还没有“从哪个方向来”。

### 4.4 辐亮度 L —— 同时对面积和立体角

这是路径追踪真正积分的量：

```text
L(p, ω) = d²Φ / (dA_perp dω)
        = d²Φ / (dA cosθ dω)
单位：W / (m^2 sr)
```

`dA_perp = dA cosθ` 是垂直于视线的投影面积。斜着看一块表面，有效面积变小，
所以分母里必须有 `cosθ`。

为什么渲染器死盯辐亮度，而不是辐照度？

1. **沿射线守恒（真空、无参与介质）**：从 A 看到 B，中间没有吸收/散射时，
   沿线的 `L` 不变。所以相机射线拿到的就是表面的出射辐亮度。
2. **传感器测的是辐亮度**：针孔相机、人眼、像素，都是在某个方向、某一小块
   投影面积上收集能量。
3. **BRDF 的两端都是辐亮度**：入射 `Li`，出射 `Lo`。

辐照度可以由辐亮度积回来：

```text
E(p) = ∫_H L(p, ω) cosθ dω
```

这不是新公式，只是把 `L` 的定义对半球积分。`cosθ` 仍然是投影面积，不是“经验 NdotL”。

## 5. 立体角：方向的面积

平面角用弧度：半径为 1 的圆上，一段弧长等于圆心角。
立体角用球面度 `sr`：半径为 1 的球面上，一块面积等于它对应的立体角。

```text
整球：  4π sr
半球：  2π sr
```

球面坐标里，方向

```text
ω = (sinθ cosφ, sinθ sinφ, cosθ)
```

`θ` 是与法线的夹角，`φ` 是绕法线的方位角。方向微元对应的球面面积是纬度圈
周长乘以 `dθ`：

```text
dω = sinθ dθ dφ
```

`sinθ` 不是装饰。θ=0 是北极（法线），那一圈周长为 0；θ=π/2 是赤道（地平线），
周长最长。丢掉 `sinθ`，等于把法线附近的方向算得过重。

本课 CPU 程序用 2048×4096 的中点黎曼和，实测：

```text
∫_H dω            = 6.283185461217     解析 2π = 6.283185307180    rel 2.45e-8
∫_H dθ dφ（错）    = 9.869604399873     = π²，既不是 2π 也不是 π
```

错误测度不是“差一点的近似”，是量错了空间。PT.3 的 PDF 会再次碰到这件事：
在方向空间均匀采样，密度必须带 `sinθ`，或者改在投影圆盘上采样。

## 6. 投影余弦：为什么是 π，不是 2π

一块表面“看见”的不是原始立体角，而是**投影立体角**：

```text
dω⊥ = cosθ dω
∫_H cosθ dω = π
```

几何意义：把半球上的每个方向投影到表面的单位圆盘，圆盘面积是 `π·1² = π`。
地平线附近的方向（θ→π/2）立体角还在，但几乎擦着表面走，对这块面积贡献接近 0。

本课实测：

```text
∫_H cosθ dω = 3.141592961600     解析 π = 3.141592653590    rel 9.80e-8
```

这就是 Lambert 着色器里 `NdotL` 的物理来源。实时管线把它写在像素着色器里；
路径追踪把它写在渲染方程的被积函数里。两边都是同一项：入射方向在法线上的投影。

常见错法：

```text
错 1  半球有 2π，所以漫反射除以 2π
错 2  把 cosθ 当成“经验暗一点”，积分时再乘一次，或干脆忘掉
错 3  用面积而不是最大边长去想 Mip（那是 R.5.5 的另一件事，不要混进来）
```

错 1 和错 2 会让能量翻倍或减半。下面 Lambert 解析解会钉死这件事。

## 7. 渲染方程：每一项都有单位

Kajiya 形式（表面、不参与介质、不考虑体积）：

```text
Lo(p, ωo) = Le(p, ωo) + ∫_H f_r(p, ωi, ωo) Li(p, ωi) (n · ωi) dωi
```

逐项：

| 符号 | 名字 | 单位 | 本节怎么理解 |
|---|---|---|---|
| `Lo` | 出射辐亮度 | W/(m² sr) | 相机最终要的量 |
| `Le` | 自发光 | W/(m² sr) | 灯的表面本身；普通墙是 0 |
| `f_r` | BRDF | 1/sr | 把入射辐亮度变成出射辐亮度的核 |
| `Li` | 入射辐亮度 | W/(m² sr) | 从 ωi 打到 p 的光；可能来自灯，也可能来自别的表面 |
| `n · ωi = cosθi` | 投影余弦 | 1 | 斜入射有效面积变小；背面为负，积半球时取 0 |
| `dωi` | 立体角微元 | sr | 方向空间的面积 |

单位闭合：

```text
[1/sr] * [W/(m² sr)] * [1] * [sr] = [W/(m² sr)]
```

BRDF 必须带 `1/sr`，否则积分完对不上辐亮度。这就是“BRDF 不是颜色贴图”的真正原因：
颜色贴图给的是 ρ 一类无量纲因子；BRDF 还要负责把半球上的方向密度除掉。

积分域是法线一侧的半球。透射、折射会把域扩到整球，那是 PT.8 的 BSDF。
本节只处理不透明表面。

`Li(p, ωi)` 本身可能还要沿射线再积分——那就是路径。本节把 `Li` 当成已知均匀场，
只验证核和测度；PT.5 才把 `Li` 换成“光源表面的 Le × 可见性”。

## 8. Lambert：为什么是 ρ/π

理想漫反射：出射辐亮度与观察方向无关，入射按余弦接收。能量守恒要求：
如果反射率是 `ρ`（0 到 1 的无量纲比例），则出射通量不能超过入射通量。

BRDF 取常数 `ρ/π`。证明只需要上一节的投影积分。

均匀入射辐亮度 `Li` 充满整个上半球时：

```text
Lo = ∫_H (ρ/π) Li cosθ dω
   = (ρ/π) Li ∫_H cosθ dω
   = (ρ/π) Li · π
   = ρ Li
```

所以：

- 白墙 `ρ=1`，均匀环境 `Li`，看到的也是 `Li`。不多造光，也不吃光。
- `ρ=0.6`，`Li=2.5`，则 `Lo=1.5`。

本课实测：

```text
rho=0.600  Li=2.500 W/(m^2 sr)  analytic Lo=rho*Li=1.500000
Lo = (rho/pi) Li ∫ cosθ dω     estimated=1.500000147064   rel 9.80e-8  PASS
forgot cosine, used ∫ dω       estimated=3.000000073547   正好两倍
```

如果有人把 BRDF 写成 `ρ/2π`，均匀入射时会得到 `Lo = ρ Li / 2`，墙只有该有的一半亮。
那是把立体角 `2π` 和投影立体角 `π` 搞混了。

Lambert 的 `1/π` 不是“除个经验系数让图好看”，是让

```text
∫_H f_r cosθ dω = ρ
```

成立。左边叫 **directional-hemispherical reflectance**，必须 ≤ 1，否则表面比入射
更亮，能量不守恒。

实时引擎里的 `float3 albedo` 往往直接当 ρ，像素着色器写 `albedo / PI * NdotL * lightColor`。
物理上这已经是同一项；差别是实时常用一个方向光近似 `Li`，路径追踪要对整个半球积分。

## 9. 代码：黎曼和在量什么

文件：`learning/sandbox/path_tracing/pt01-radiometry/pt1_radiometry.cu`

积分核（中点矩形，双精度）：

```text
dθ = (π/2) / 2048
dφ = 2π / 4096
θ  = (i + 0.5) * dθ          // 格子中点，避开 θ=0 处 sinθ=0
dω = sinθ dθ dφ

solid_angle            += dω
projected_solid_angle  += cosθ * dω
forgotten_sine         += dθ * dφ     // 故意用错测度
```

然后：

```text
Lo_numeric  = (ρ/π) * Li * projected_solid_angle
Lo_analytic = ρ * Li
Lo_wrong    = (ρ/π) * Li * solid_angle     // 用 2π 代替 π
```

验收阈值相对误差 `< 1e-6`。本机 RTX 5070 上用 `build.ps1` 编译运行，三个正确积分
都在 `1e-7` 量级，错误测度明确不等于 `2π` 或 `π`，忘掉余弦明确得到两倍能量。

这还不是蒙特卡洛。黎曼和按固定格子遍历整个半球，方差来自离散化，不是随机采样。
PT.3 会把同一个积分改成 `f(ω)/pdf(ω)` 的随机估计；那时解析值 `2π`、`π`、`ρ Li`
仍然是对照答案。

## 10. 商业引擎 vs 本课

| | UE5 / 生产路径 | 本课 PT.1 |
|---|---|---|
| 内部工作空间 | 线性场景辐亮度，后处理再 tone map | 同样：线性 radiometric 单位 |
| 实时 GI | Lumen：探针、Radiance Cache，不直接积完整渲染方程 | 不实现 Lumen |
| 参考图 | Path Tracer：DXR 求交 + MIS 积分 | 本节连射线都没有，只验证核 |
| Lambert | `albedo/π` 出现在材质/BxDF 里 | 显式数值积分证明 `ρ/π` |
| 单位 | 引擎常把“1 个单位”当无量纲场景值 | 本节强制写出 W、sr、m²，防止除错系数 |

相同的底层机制：出射辐亮度 = 自发光 + 半球上 `BRDF × Li × cosθ` 的积分。
引擎用缓存、探针、硬件光追去逼近这个积分；本课先把积分本身算对。

## 11. 本节明确暂缓的内容

- **相机射线、像素滤波**：PT.2。现在还没有“图像”。
- **几何求交 / 可见性**：PT.2。`Li` 被当成已知场。
- **蒙特卡洛、RNG、无偏估计**：PT.3。黎曼和只证明解析值，不是渲染算法。
- **余弦加权半球采样**：PT.4。知道 `∫ cosθ dω = π` 之后，才能写出 `pdf = cosθ/π`。
- **NEE / MIS / 多次反弹 / 俄罗斯轮盘赌**：PT.5–PT.7。
- **金属、介质、微表面**：PT.8。BRDF 不再是常数。
- **Tone mapping / sRGB 显示**：PT.10。沿用 R.5.4 的线性工作空间约定。

## 12. 小结

```text
Radiometry 管能量，Photometry 管人眼加权；积分必须在 Radiometry
Φ[W] → I[W/sr] → E[W/m²] → L[W/(m² sr)]，路径追踪积分的是 L
dω = sinθ dθ dφ；半球 ∫ dω = 2π
投影余弦来自有效面积；半球 ∫ cosθ dω = π，不是 2π
渲染方程：Lo = Le + ∫ f_r Li cosθ dω，单位必须闭合
Lambert f_r = ρ/π，均匀 Li 时 Lo = ρ Li；忘掉余弦会得到 2ρ Li
Lumen ≠ Path Tracer ≠ DXR
```
