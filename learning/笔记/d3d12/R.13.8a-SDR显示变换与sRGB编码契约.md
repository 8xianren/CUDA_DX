## 1. 输入、输出与假设

输入H是未曝光scene-linear RGB历史平均值。本课将RGB解释在线性sRGB原色/D65白点下，非负、有限；不是任意光谱数据，也没有自动相机标定。线性表示加光/乘比例等操作在线性域进行，不代表数值必在[0,1]。

目标为SDR、sRGB解释的8-bit RGB输出。H=1不是自动对应某个nit；曝光与映射约定才决定显示白。HDR场景数据不等于HDR显示输出。广色域转换、HDR10/PQ、scRGB、OS显示校准均不在本节范围。

流程：H -> E*H -> T(E*H) -> S(T(E*H)) -> Q8。每步返回新值，不改历史。

## 2. 曝光补偿

每增加一档相对曝光补偿，乘数加倍；零档乘数1，故E=2^c。c是相对补偿EV，不是由光圈/快门/ISO求得的绝对相机EV。c=-1/0/+1对应0.5/1/2。本程序限制[-16,16]并拒绝非有限输入。

曝光是乘法，不压缩动态范围。若直接截断，x=1/4/16都会变白。曝光放在tone mapping之后一般不等价：T(2*1)=2/3，而2*T(1)=1。

### 物理曝光量、相机设置EV与曝光补偿的区别（2026-10-15答疑）

“曝光决定观察尺度”指线性光照到显示处理输入的数值倍率，不是空间缩放。必须区分以下三个量。为避免与本文历史RGB的H、曝光倍率E混淆，本段用H_s表示物理曝光量、E_s表示传感器辐照度。

1. **物理曝光量（这里指辐射曝光量）**：H_s = ∫ E_s(t) dt，积分范围为快门打开的时间。E_s单位W/m²，表示传感器单位面积每秒接收的光能；H_s单位J/m²，表示这段时间单位面积收到的总光能。光照恒定时H_s = E_s·Δt。例如E_s=2 W/m²，曝光0.01秒得到0.02 J/m²，曝光0.02秒得到0.04 J/m²。它不是无单位的EV，也不是历史RGB数值。
2. **相机设置的曝光值EV**：定义EV = log₂[N²/(Δt/1秒)]。时间按秒取数值时常简写log₂(N²/t)。在相同场景辐亮度L、理想近轴成像和固定镜头透射等条件下，E_s ∝ L/N²，因而H_s ∝ L·Δt/N²。保持L等条件不变，可得H_s ∝ 2^(-EV)。这是正比关系，不是H_s = 2^(-EV)。相机设置EV增加1，对应曝光量减半；例如固定光圈，将快门从1/100秒缩短到1/200秒。该定义本身不含ISO；EV100涉及感光度归一化/标定，不能与本课相对补偿混用。
3. **本程序的相对曝光补偿c**：规定正值使画面更亮，倍率E=2^c。补偿+1档对应乘2，0档对应乘1，-1档对应乘0.5。这不是把上述相机设置EV增加1，两者正方向不同。代码只做线性RGB乘法，没有模拟真实光圈、快门、传感器响应或ISO增益；实际改变光圈/快门还可能改变景深/运动模糊。

**光圈数是什么？** 光圈是镜头中限制通光束的开口；光圈数N=f/D，其中f为焦距，D为入瞳直径（从镜头前方看进去的有效开口直径，不一定等于光圈叶片的实际孔径）。例如50 mm镜头：入瞳直径25 mm对应f/2，12.5 mm对应f/4。在相同场景和上述近似条件下，f/4的传感器辐照度约为f/2的1/4，因为1/N²从1/4变为1/16。因此数字越小，开口相对越大，进光越多；f/2到f/2.8（精确为2√2）约减一档光，f/2到f/4减两档光。比较曝光时还须保持快门时间等条件一致。

术语约定：后文“曝光+1EV”默认指本程序的相对曝光补偿c=+1，而不是相机设置EV增加1。固定倍率乘法与平均可交换；随帧变化的倍率不能未经尺度统一直接混入历史。本课始终保存未曝光历史，再统一执行曝光→色调映射→sRGB编码→量化。

## 3. 从约束构造教学色调映射

选一个简单有理函数族T(x)=a*x/(b+x)，x>=0。约束：黑为黑、无穷大渐近1、黑附近斜率1。第二个约束给a=1，第三个给a/b=1，所以b=1，得T(x)=x/(1+x)。其导数1/(1+x)^2>0，有限x映入[0,1)，强光差别被压缩而不是直接截断。

这些约束并不唯一决定所有可能曲线；先选函数族才得到该解。这里使用逐RGB通道的简单Reinhard形式，可能改变通道比例与饱和度，不等同于亮度版本的完整摄影tone mapping，也不是UE的完整film/color grading管线。

T(0)=0，T(1)=0.5，T(4)=0.8，T(16)=16/17。它把场景相对强度变成显示端线性RGB。下面仍要进行sRGB编码。

## 4. sRGB编码与量化各做什么

8位只有256个码值。若线性均分，它们在暗部提供的相对精度不足。sRGB采用非线性分配码值，并有相应的解码规则；正确编码不是额外的美术增亮。原色/白点与传递函数是不同部分，本课保持相同原色，只研究传递函数。

对显示端线性分量l∈[0,1]：

```
S(l) = 12.92*l                         l <= 0.0031308
       1.055*l^(1/2.4) - 0.055        其余
```

这些常数来自sRGB约定，不由本课图像推导，不能用单纯pow(l,1/2.2)替换后称完全一致。alpha不使用RGB的sRGB编码。

Q8(s)=floor(255*clamp(s,0,1)+0.5)。本CPU明确用half-up，未来硬件恰好半码点的tie规则可能不同，不能要求所有边界都与CPU逐字节相等。先编码后量化；不能先丢精度再期望编码恢复暗部。

显示端线性0.5：漏编码Q(0.5)=128；正确Q(S(0.5))=188；重复Q(S(S(0.5)))=223。码值增大不表示期望物理亮度从0.5增到0.735；正确显示解释会解码。

## 5. 将来GPU的两个合法搭配

|像素shader输出|RTV格式|编码位置|
|---|---|---|
|T(EH)，显示端线性|兼容的*_UNORM_SRGB|RTV输出转换做一次sRGB|
|S(T(EH))，已编码|*_UNORM|shader做一次sRGB|

把已编码RGB写入SRGB RTV会重复；把未编码线性RGB写入普通UNORM RTV会漏掉。UNORM只表示无符号整数归一化存储/访问约定，不意味着自动sRGB。资源格式、视图格式、字节实际表示与展示路径必须一起核对。不能仅因交换链格式名称没有SRGB就断定图像不需要编码。

SRV的SRGB转换是读取时解码，RTV是输出时编码，不是给任意UAV/Copy操作贴上名称就自动转换。未来GPU显示pass选择明确的一条路径并读回验证；混合、UI与HDR输出留到对应阶段，不能照搬本CPU预览。

官方依据：[Microsoft颜色空间转换](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/converting-data-color-space)、[DXGI_FORMAT](https://learn.microsoft.com/en-us/windows/win32/api/dxgiformat/ne-dxgiformat-dxgi_format)。微软页面简述中把sRGB称gamma2.2，但同时明确实际是线性段+2.4幂；本课使用实际分段公式。

## 6. 实现、布局、所有权与失败路径

- `dxr_display_reference.h`：double标量参考，exposure_multiplier(c)、reinhard(x)、srgb_encode(l)、srgb_decode(s)、quantize8(s)、display_linear(H,c)、display_byte(H,c)。参数和返回值域写在函数注释，无全局可变状态。
- `dxr_display_probe.cu`：CPU独立数值锚点/扫描、PFM加载、BMP输出。只支持课程PF/-1.0小端float32；每像素RGB12字节，文件bottom-up，读入vector时转为top-down。ifstream/vector由作用域管理，不修改原PFM；坏头、截断、额外数据、非有限/负光照值抛异常，main打印FAIL并返回1。
- BMP采用显式小端字段而非裸结构体，BGR8顺序，行4字节对齐、bottom-up。没有嵌入ICC profile，作为sRGB诊断预览使用，数值验收以CSV为准。
- `dxr_display_preview.ps1`：System.Drawing只做标题与BMP转PNG，不重算显示变换；finally释放Image/Bitmap/Graphics/Font。输入由C++输出，路径从脚本目录定位。
- 本程序无GPU资源、Fence或异步生命周期。GPU pass需要的历史UAV->SRV访问、Back Buffer状态与帧资源同步在R.13.8b实现后单独验证。
