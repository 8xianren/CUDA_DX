# G.6：从三维椭球推导屏幕上的高斯椭圆

[课程工程](../../sandbox/d3d12/neural-rendering/README.md) · [投影实现](../../sandbox/d3d12/neural-rendering/src/gaussian/projection_math.cuh) · [G.7](G.7-分桶前缀和与稳定排序.md)

本节目标是回答一个几何问题：一个有位置、旋转和尺度的三维高斯，经过透视相机以后，在屏幕哪里、覆盖多大区域、应该用什么权重？先解决表示与几何，下一节再解决 GPU 如何为像素找到候选高斯。

## 1. 从粒子类比走到真实数据模型

游戏粒子常用面向相机的矩形贴片。3DGS 的一个基本元素也会形成屏幕上的软斑点，但它的世界几何是一个三维椭球分布。相机移动时，斑点的形状通过投影变化，不是始终保持固定大小的圆形贴图。

不要把高斯当成一块真正的透明实体表面，也不要把它的 opacity 直接等同于 G.1 中单位长度的消光系数。这里采用显式高斯表示和专用 Alpha 合成；它可以拟合图像，却不自动拥有物理材质、表面法线或光源响应。

`gaussian.h` 的 `Gaussian` 保存：

|字段|布局与单位|含义|
|---|---|---|
|`mean[3]`|世界坐标 XYZ|椭球中心 μ|
|`scale[3]`|三个正数，世界长度|三个主轴的标准差，而非方差|
|`rotation[4]`|w,x,y,z|主轴旋转四元数，投影时归一化|
|`opacity`|有限值 [0,1]|二维高斯峰值 Alpha 参数|
|`sh[48]`|基函数索引优先，每基 RGB 交错|最多 16 组 RGB 球谐系数|
|`shDegree`|0、1、2、3|有效基函数数为 (degree+1)²|
|`id`|唯一 uint32|资产稳定身份；数组打乱后保持原值|

这些是运行时值。Graphdeco PLY 存储的尺度通常在对数域，opacity 在 logit 域，必须由 G.9 的资产层显式解码。渲染层不根据“数值长得像什么”猜格式。

## 2. 为什么旋转与尺度能产生半正定协方差

先取各方向独立、方差为 1 的随机向量 ξ，满足 E[ξ]=0、E[ξξᵀ]=I。用尺度矩阵 S=diag(sx,sy,sz) 拉伸，再由旋转 R 改变方向，最后平移到 μ：

```text
X = μ + R S ξ
```

协方差定义为 E[(X−μ)(X−μ)ᵀ]，代入上式：

```text
Σworld = R S E[ξξᵀ] Sᵀ Rᵀ
       = R diag(sx²,sy²,sz²) Rᵀ
```

对任意向量 a，`aᵀΣa = ||S Rᵀa||² >= 0`，因此它天然半正定，不需要训练时直接优化六个独立矩阵元素后再“修补负特征值”。本课要求尺度严格为正且大于 1e-7，于是非退化轴形成正定矩阵；过小尺度、零四元数与非法 opacity 会按原因剔除。

这里的“协方差”描述分布沿方向展开的宽度。它不是颜色，也不是内存布局。旋转和尺度是参数编码；AoS/SoA 是存储组织，二者独立。

## 3. 相机换基与透视 Jacobian

本课明确采用相机 +Z 朝前、+Y 朝上，像素 +Y 朝下；世界到相机是刚体变换 `q=Wμ+t`。`Camera.worldToCamera[12]` 按行存放三个 `[rotation row, translation]`。所有坐标约定都是接口约定，不能把 OpenGL 的 −Z 前方矩阵直接塞进去。

平移不改变协方差；旋转换基给出 `Σcamera=W Σworld Wᵀ`。透视图像坐标定义为：

```text
u = fx x/z + cx
v = cy − fy y/z
```

`fx,fy` 的单位为像素，`cx,cy` 是主点。像素采样点采用 `(pixelX+0.5,pixelY+0.5)`；本课不混入上游不同的整数像素中心约定。

透视不是线性变换，因此三维高斯透视后的分布并不严格还是高斯。我们在中心 q 附近做一阶 Taylor 展开：`π(q+δq)≈π(q)+J δq`。逐项求偏导，得到：

```text
J = [ fx/z      0      −fx*x/z² ]
    [  0      −fy/z     fy*y/z² ]
```

第二行的负号来自像素向下，不是随意加入的“修正”。如果忽略它，倾斜椭圆的 xy 协方差就会镜像。

根据线性变换协方差公式，`Σ2D = J W R S Sᵀ Rᵀ Wᵀ Jᵀ`。令 `A=WRS`、`B=JA`，便能用 `B Bᵀ` 直接算出二维对称矩阵的三个数 xx、xy、yy，避免暂存完整的两个 3×3 矩阵。实现位于 `projection_math.cuh:51`。

本课给 xx、yy 各加 `0.3 pixel²` 低通项，防止亚像素斑点变成奇异尖峰。这是重建滤波选择，不是从透视几何自然推出的常数。它会改变非常小高斯的形状与能量；精细抗锯齿/能量补偿属于生产实现的进一步工作。

## 4. 从协方差得到权重与包围范围

二维矩阵写成 `[[xx,xy],[xy,yy]]`，行列式 det=xx·yy−xy²。若 det 非正或非有限，不能求逆，要记录退化原因。逆矩阵为：

```text
Σ2D⁻¹ = (1/det) [ yy  −xy ]
                  [−xy   xx ]
```

令 A=yy/det、B=−xy/det、C=xx/det，像素偏移 d=(dx,dy) 的权重指数是 `−0.5(A dx²+2B dxdy+C dy²)`。xy 项出现两次，因为矩阵两侧各贡献一次。

要找到候选范围，先求最大的特征值：

```text
λmax = (xx+yy)/2 + sqrt(((xx−yy)/2)²+xy²)
radius = ceil(3 sqrt(λmax))
```

最大主轴半径给出保守圆，再取它的屏幕矩形并裁剪至 viewport。真正 splat 时还会检查椭圆方程，只积累 `dᵀΣ⁻¹d<=9` 的区域。高斯本来无限延伸；3σ 截断是本课明确的近似，不能说它在边界以外数学上变成零。

剔除顺序包括：非有限属性、非法尺度/四元数、中心在 near plane 后侧、退化协方差、超过 maxRadiusPixels 的极大斑点、离屏。中心深度剔除也是近似：穿过近裁剪面的巨大高斯需要更精细处理，本课选择显式拒绝来避免未定义投影。

## 5. 球谐颜色：角度函数，不是几何旋转

球谐函数 SH 是定义在单位球方向上的一组基函数。类似 Fourier 用正弦余弦表达一维信号，SH 用一组方向函数表达随视角变化的颜色。degree=0 只有常数项，degree=1 加三个线性方向项，degree=3 一共 16 项。

本课方向是世界空间从相机指向均值的单位向量 `(μ−cameraPosition)/length`。颜色计算为 `max(0,0.5+Σ coefficient[k,channel]·SH_k(direction))`，DC 基函数常数为 `0.28209479177387814`。所以若只想得到固定 RGB，DC 系数写成 `(RGB−0.5)/0.28209479`。SH 只改颜色，不改 μ、R、S；更高阶可以拟合角度相关外观，但不因此自动得到可重光照 BRDF。

## 6. 本机验收与动手

从仓库根运行：

```powershell
& learning/sandbox/d3d12/neural-rendering/tests/gaussian/build.ps1
```

真实结果在 [projection.json](../../sandbox/d3d12/neural-rendering/results/g6/projection.json)。已验证中心球、90° 椭球旋转、像素 Y 翻转等 4 个解析断言；对 128 个高斯逐个比较 CPU/CUDA 中心、z、xx/xy/yy 和半开包围矩形，最大绝对误差 `2.622604370e-6`，矩形全部相同。五种恶劣输入分别得到 behind_camera、degenerate、oversize、offscreen、non_finite。

CPU/CUDA 共用纯数学公式，因此单纯二者相等不能证明公式正确。解析球测试独立要求 `fx=100,z=2,s=.2` 时 xx=yy=100.3；再用 90° 旋转检查长短轴交换。列表构建和图像合成则有独立 CPU 算法，见后两节。

练习答案直接给出：把 s 加倍，协方差几何项放大 4 倍、屏幕标准差约放大 2 倍；把 z 加倍且中心在光轴上，几何项缩小到 1/4。0.3 的低通项不会同步缩放，因此非常小的斑点不严格满足半径同比关系。

商业引擎会将资产解码、裁剪、GPU 数据组织和多帧资源管理分层，并可能对大高斯使用更精确投影。我们保留同样的协方差/Jacobian 机制，以透明可读的 AoS 与同步验收暴露每一步；这不是完整商业 3DGS 插件。

参考：[Graphdeco 官方前向实现](https://github.com/graphdeco-inria/diff-gaussian-rasterization/blob/main/cuda_rasterizer/forward.cu)；本课保留自己的相机与像素中心契约，不承诺逐像素复刻其渲染器。
