# F.3 FXAA：从局部对比度到沿边搜索

[F 主线程序](../../sandbox/d3d12/aa-reconstruction/README.md) · [F.4 输入契约](F.4-时域重建输入契约.md)

目标是能解释“这个像素为什么要混合、往哪个方向混合、混合多少”，并在同一个 GPU 光栅场景中比较 No AA、MSAA 和 FXAA。代码入口是 `shaders/post.hlsl:38` 的 `FxaaCS`；本课是有端点搜索的教学实现，不是宣称逐位复刻 FXAA 3.11 某个质量预设。

## 1. 要解决的问题

在 F.1 中，MSAA 根据多个覆盖样本估计几何边缘的面积；到本节，几何已经变成一张单采样颜色图。我们无法从颜色图恢复“真正的三角形覆盖”，只能从阶梯形亮暗边界估计连续边缘应经过哪里。

可以把它想成美术拿到一张已经栅格化的斜线，沿阶梯寻找原来的轮廓，再把边界附近的颜色重新分配。没有几何、没有历史，意味着这种修补也可能把纹理图案当作轮廓。它解决的是当前帧中可见的空间不连续，不能保证下一帧细线仍采到相同亮度。

## 2. 从约束推导方向与偏移

先约定纹理 UV 原点在左上，像素中心为 `(x+0.5,y+0.5)`。颜色在线性 RGB 中保存。亮度检测使用 `sqrt(max(dot(rgb, Rec709),0))`，平方根让暗部对比在阈值中占较合适的比例；它不是 sRGB 编码函数，滤波结果也不在平方根亮度域输出。

第一步只读中心与上下左右。设最大亮度为 `Lmax`、最小为 `Lmin`，对比跨度 `R=Lmax-Lmin`。同时使用绝对阈值和相对阈值：

```text
R < max(minThreshold, relativeThreshold × Lmax) → 原样输出
```

绝对阈值抑制极暗噪声，相对阈值避免很亮但相对变化很小的区域触发滤波。二者都属于质量参数，不能从几何定理推出唯一默认值。本课分别为 0.0312 和 0.125。

第二步把采样补成 3×3。若边界大致水平，亮度应主要沿竖直法线变化，所以比较沿 x/y 的二阶差分能量，而不是仅根据一阶梯度。为什么不只用一阶差分？一条中心正好落在像素上的细亮线，两侧同样暗，左右一阶差可能抵消；二阶差能看见“中间凸起”。

第三步在法线两侧选与中心亮度差更大的那个邻居，把中心与该邻居的中点作为近似边界。沿切线向两侧搜索，直到采到的亮度相对边界均值变化达到所选法线梯度的四分之一，或达到 12 次搜索上限。切线负责寻找边缘端点，最终采样偏移却沿法线：二者不能混为同一个方向。

若两侧距离为 `d−`、`d+`，中心离较近端越近，所需偏移越大，构造：

```text
offset = 0.5 − min(d−, d+) / (d− + d+)
```

中心恰在两个端点中间时偏移为 0；接近一端时趋近半个像素。这是局部边缘覆盖的启发式估计，不是精确面积积分。如果近端与中心在边界均值同侧，移动方向可能错误，取消这个偏移。另外用 3×3 低通均值与中心的差估计亚像素细节，得到 subpixel 偏移，取两种偏移的较大者。

## 3. 实际 shader 与资源

`FxaaCS` 的 `[numthreads(8,8,1)]` 表示一组 64 个线程；每线程输出一个像素，host 应调用 `Dispatch(ceil(W/8),ceil(H/8),1)`。边界线程先检查尺寸；本入口要求输入与输出同尺寸，不能顺手把空间超分混进 FXAA 对照。

它读取 `t0=currentColor`，写 `u0=outputColor` 与 `u1=diagnostic`，`s0` 是 linear clamp 采样器。RGBA16_FLOAT 和 RGBA32_FLOAT 均可经 `Texture2D<float4>` 访问；前者量化误差应单独考虑。输入不能同时是输出资源，否则邻线程会读到部分本帧写入值，结果依赖执行顺序。

整数邻域使用 `Texture2D.Load(int3(pixel,0))`，显式 `clamp` 到边界；连续端点与偏移使用：

```hlsl
currentColor.SampleLevel(linearClamp, uv, 0)
```

三个参数依次是采样器、归一化二维坐标和显式 mip 层。Compute Shader 不使用像素 shader 的隐式屏幕导数选 mip，因此这里明确选 0。相关接口见 [Microsoft SampleLevel 文档](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-to-samplelevel)。

host 负责将输入转为 `NON_PIXEL_SHADER_RESOURCE`、输出转为 `UNORDERED_ACCESS`。后续显示或下一 pass 读取前必须有状态转换或相应 UAV 依赖；CPU 读回需等覆盖 copy 的 Fence，不能以“dispatch 已录制”当作“结果已经完成”。

诊断纹理四通道为：水平边判断、最终偏移、两侧搜索距离之和、是否触发过滤。FXAA 的这组诊断语义与 TAA 诊断不同，查看时必须先知道当前入口。

## 4. 动手与判读

从仓库根目录构建/运行本课 README 的统一命令。真实场景包含窄斜线、棋盘 mip、alpha-tested 叶片、旋转遮挡物与透明粒子；所有 AA 模式保持同一场景和曝光。GPU 时间应读取 timestamp，不用 CPU 提交耗时替代。

F.1 单独比较 4× MSAA 的 alpha clip 与 Alpha-to-Coverage（A2C），用来观察覆盖率机制；F.10 的统一质量序列则让 **No AA、MSAA4、FXAA 和 reference 都保持相同 alpha clip(0.5) 规则**，MSAA4 不额外开启 A2C。否则叶片区域的差异同时来自覆盖材料语义变化，不能全算成抗锯齿质量。单项机制演示与控制变量评测必须分开。

先观察斜线轮廓，再观察远处细线与纹理。FXAA 可以改善当前阶梯，但也可能降低高频对比。接着让相机平移，比较帧序列：静帧变平滑并不等于运动时没有闪烁。2026-10-22 已在 RTX 5070 的真实 D3D12 场景完成 **120 帧 FXAA 序列**，输出 640×360，Debug Layer 验证开启；运行结果见 [FXAA 序列报告](../../sandbox/d3d12/aa-reconstruction/results/f10/sequences/fxaa/summary.json)。为保证对照共用同一场景，F.3 的最终帧序列/数值集中在 `results/f10/`，没有复制另一套 F.3 场景。正式 GPU 性能使用独立 benchmark，启用调试并逐帧读回的 sequence 不作为端到端性能；shader 编译成功本身也不是 GPU 运行验收。

商业引擎往往把 FXAA 放在有明确色彩空间约定的后处理链中，并使用经过调校的质量 preset。本课直接在线性 HDR 纹理上做颜色滤波、以感知亮度检测方向，方便和 TAA/超分保持相同输入。算法机制相通，默认参数和最终观感不可据此等同于某个引擎的产品设置。

最终 120 帧质量数据采用同帧 2560×1440 光栅化、4×4 box 缩到 640×360 的有限采样参考。显示域先做固定曝光的 Reinhard 与 sRGB，MAE 越小、PSNR 越大代表与该参考越接近；参考本身不等于解析真值。

|同尺寸方法|线性 HDR MSE|显示域 MAE|显示域 PSNR/dB|参考误差的相邻帧变化 RMS|
|---|---:|---:|---:|---:|
|No AA|0.004246|0.009803|29.851|0.010866|
|4× MSAA，同样 alpha clip|0.001455|0.008032|32.619|0.004263|
|本课 FXAA|0.003768|0.017828|27.161|0.010020|

这个结果没有支持“FXAA 全面提升画质”：本课 FXAA 的 HDR MSE 略低于 No AA，但显示域 MAE 更大；静态背景 ROI 的显示域 MAE 从 0.022589 增为 0.044478，与棋盘、细线被滤软的图像现象一致。边缘搜索能减少某些锯齿，也可能误伤高频纹理。最后一列对相邻帧的**参考误差**求差，并排除 Camera Cut，不把物体本身的运动直接计作闪烁，也不能代替完整感知评价。详见 [最终质量表](../../sandbox/d3d12/aa-reconstruction/results/f10/quality/metrics.csv) 和 [同帧联系图](../../sandbox/d3d12/aa-reconstruction/results/f10/quality/contact-sheet.svg)。

最终F.10统一alpha-clip、固定输出投影的120帧结果：NoAA / MSAA4 / 本课FXAA的显示MAE分别为 **0.009803 / 0.008032 / 0.017828**，PSNR为29.851 / 32.619 / 27.161 dB。关闭调试、去掉8帧预热后的场景加重建GPU均值分别为0.02043 / 0.03643 / 0.03022 ms；MSAA总区间包含Resolve。FXAA在本场景软化高频棋盘，不能因为名称里有抗锯齿就预设误差一定小于NoAA。完整范围与限制见[F10](F.10-固定序列质量与性能评测.md)。

## 5. 自测题与答案

**为什么不把 3×3 平均称为 FXAA？** 因为平均没有方向和边缘端点概念，平坦纹理也会被普遍模糊；本课先选边再沿边搜索，最后只对需处理的像素偏移取样。

**FXAA 能修复没有被当前帧采到的细线吗？** 不能可靠恢复。没有样本就是缺少信息，当前颜色无法证明那里本来存在一根线。

**为什么它不需要 Motion Vector？** 所有读操作来自当前帧；没有历史对应关系，自然不需要跨帧运动信息。下一节才建立跨帧证据。

算法背景来自 [NVIDIA FXAA 白皮书](https://developer.download.nvidia.com/assets/gamedev/files/sdk/11/FXAA_WhitePaper.pdf)；此处推导、阈值与实现为课程自编，保留教学限制。
