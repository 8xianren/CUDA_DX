# 3.2 CUDA Streams（流）

> 对应仓库：`tutorials/cuda-cpp/notebooks/02.03-Streams/`
> 本地 demo：`learning/sandbox/cuda/03-streams-profiling/streams_overlap.cu`（实测 1.99x 加速）
> 官方文档：CUDA Programming Guide §「Asynchronous Concurrent Execution / Streams」

## 一句话目标
3.1 让 **GPU 与 CPU** 重叠；本节用 **stream** 让 **GPU 上的多个操作**（计算 kernel、数据拷贝）互相重叠并发。

---

## 一、为什么需要 stream：反直觉的坑
把拷贝换成 `cudaMemcpyAsync` 并**不会**自动让计算和拷贝重叠。因为：

> **同一个 stream 里的所有操作，严格按发射顺序串行执行（in-order）。**

不指定 stream 时，所有操作都进**默认流（default stream）**这一条队列，排队串行。`cudaMemcpyAsync` 对 CPU 异步（发射即返回），但和后面的 kernel 在同一队列里，GPU 仍逐个执行，没有重叠。

心智模型：**stream = GPU 上的一条有序工作队列**。想让两件事并发，得放进两条不同的队列。

---

## 二、核心规则（全章地基）
```
同一个 stream 内：严格按顺序执行   —— 保证依赖正确（拷入→计算→拷出）
不同 stream 之间：互不等待，可并发  —— 并发的来源
```
有依赖的步骤放同一流（自动保序）；互不依赖的批次放不同流（并发）。

---

## 三、API 四件套
```cpp
cudaStream_t s;                  // 1. 类型
cudaStreamCreate(&s);            // 2. 创建
cudaStreamSynchronize(s);        // 3. 只等这条流
cudaStreamDestroy(s);            // 4. 销毁
```
把操作发射到流：
```cpp
kernel<<<grid, block, 0, s>>>(...);                 // kernel 第 4 个 <<<>>> 参数
cudaMemcpyAsync(dst, src, bytes, kind, s);          // 最后一个参数
cub::DeviceReduce::Sum(d_temp, sz, in, out, n, s);  // CUB 等库收尾都带 stream 参数（默认 0）
```
**规律**：几乎所有 NVIDIA 加速库（CUB/cuBLAS/cuDNN…）函数结尾都有可选 `cudaStream_t stream = 0`，预期你会想重叠。

---

## 四、同步粒度对比
| 函数 | 等谁 | 粒度 |
|---|---|---|
| `cudaDeviceSynchronize()` | 整个 GPU 所有流 | 粗 |
| `cudaStreamSynchronize(s)` | 只等流 s | 细 ✅ 推荐 |
| `cudaEventSynchronize(e)` | 等事件 e 触发 | 最细 |

只在需要某流结果时等它，别动辄全局同步抹掉并发。

---

## 五、关键新知识：锁页内存（pinned memory）
> **`cudaMemcpyAsync` 只有在 host 内存是「锁页(pinned)」时才真正异步；否则退化成同步，重叠失效！**

- 普通 `malloc` 内存是**可分页(pageable)**的，OS 可能换出到磁盘；DMA 不能容忍，驱动得先中转拷贝到临时 pinned 缓冲（同步）。
- **锁页内存**钉死在物理内存，DMA 直接搬，拷贝才真异步。
```cpp
float* h; cudaMallocHost(&h, bytes);   // 锁页内存
// cudaMemcpyAsync(..., h, ...) 才真异步
cudaFreeHost(h);
```
代价：占真实物理内存、分配慢，别滥用。

## 六、CUDA Event（事件）与跨流依赖
- **`cudaEvent_t`**：GPU 时间轴上的标记点/路标。
- `cudaEventRecord(e, s)`：在流 s 当前位置插标记，流执行到此处时 e 触发。
- `cudaStreamWaitEvent(s2, e, 0)`：让流 s2 暂停，直到 e 触发——用于跨流依赖（如拷贝流等计算流算完某块再拷）。
- `cudaEventElapsedTime(&ms, t0, t1)`：测两事件间 **GPU 时间轴**耗时，比 CPU 端 chrono 更准。

作用：在"完全独立（并发）"和"完全串行"之间架精确依赖桥。

## 七、demo：双流重叠（1.99x）
`learning/sandbox/cuda/03-streams-profiling/streams_overlap.cu` 把工作切成 8 块流水线：
- 方案 A 单流：`heavy` 和 `cudaMemcpyAsync` 同一流 → 串行（1.96ms）。
- 方案 B 双流：计算流 `cs` + 拷贝流 `ps`，用 event 建跨流依赖 → 重叠（0.99ms）。
- 结果：**1.99x**。第 c 块往 CPU 拷时，计算流已在算第 c+1 块。

## 八、工程实战：数据竞争修复 + 带宽分层（仓库 streams.cpp）
模拟器想"拷 `d_prev` 回 CPU"的同时"计算流继续更新 `d_prev`" → **边读边写，数据竞争**。
修复：加 GPU 暂存缓冲 `d_buffer`：
1. 计算流里 `d_prev` → `d_buffer`（GPU→GPU，极快）。
2. 拷贝流 `d_buffer` → CPU（慢，但读快照，不怕被覆盖）。
3. 计算流继续更新 `d_prev`，互不干扰。

为何仍划算 —— **带宽分层（新知识）**：
> GPU↔GPU 带宽 ≫ GPU↔CPU（PCIe）带宽。

数字感（Ampere / PCIe 4.0）：GPU 显存带宽 ~360 GB/s，PCIe 4.0 x16 ~25 GB/s，差 10 倍以上。
用一次廉价 GPU→GPU 快照，解锁昂贵 GPU→CPU 传输与计算的重叠。
**铁律：尽量减少 host↔device 数据搬运。**
